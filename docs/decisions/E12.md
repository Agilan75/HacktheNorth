# E12 — sweep observations + pair rules

## D1 — Dedupe is greedy by confidence
Sort by confidence desc (stable), then `dedupeByBearing(±15°, same label)`. The
cluster's best observation survives unchanged; survivors are returned in input
order. A survivor inherits `runsSeen: 2` if any merged member had it. Idempotent.
Rejected: transitive chaining (10°, 24°, 38° collapsing into one) — it would merge
objects 28° apart.

## D2 — Self-consistency is a one-to-one match
Each run is deduped, then run-A objects (strongest first) claim the closest
unmatched run-B object of the same label within ±15°. Matched → higher of the two
confidences, `runsSeen: 2`, `ceilingVisible` OR-ed. Unmatched on either side →
confidence × 0.5, `runsSeen: 1`. An empty run B halves everything.

## D3 — Ceiling share = share of frames
`ceilingShare = distinct frameIndex with some observation ceilingVisible ÷ coverage.frameCount`.
Frames are captured every ≥10° so frame share tracks sweep share, and
`CoverageResult` carries no FOV. Threshold is inclusive (`>= 0.5`), per PRD 9.3 and
`CEILING_COVERAGE_REQUIRED`'s doc; `rules/tenant.json` TN-SMOKE-CEILING says "more
than 50%" — the PRD/constant wording was kept. **A18 must attach `ceilingVisible` to
at least one observation per frame** (an `unknown`-label observation is fine) or a
ceiling-only frame is invisible to this count.
`negativeEvidence` returns `{ path: 'hazards.smokeDetector', value: false, confidence: share }`;
`toHazardValues` turns it into `hazards.smokeDetectorCount = 0` (the slot the rule reads).

## D4 — Absence on a sufficient sweep is `false`
With `coverage.sufficient`, an unseen visible hazard (7 presence labels,
`highValueContents`, heater-near-combustible, power bar when no power bar seen) is
recorded `false` at confidence = coveragePct/100. Below 75% it stays unknown and
`unknownHazards` lists it. The smoke detector is the only exception (ceiling rule).
Rejected: never inferring `false` — every tenant sweep would ask ~10 questions and
the "camera replaces the form" goal fails.

## D5 — Pair rules
All qualifying (a, b) pairs are returned; hit confidence = conf(a) × conf(b).
`toHazardValues` uses the strongest hit. `derived` observations never count as sightings.
`powerBarOverload` is left to the `relate` call whenever a power bar was seen.

## D6 — Output shape
Paths use the PRD spelling `hazards.<key>` (merge resolves both). `highValueContents`
is emitted as boolean (tenant vector component is binary; question is boolean),
unlike merge's count. `ceilingObserved` is emitted true/false whenever frameCount > 0.
**A18: feed `toHazardValues` output OR raw observations to the engine, not both,**
or presence values are appended twice (same value, so no contradiction, but noise).
