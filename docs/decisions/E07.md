# E07 — price (commercial, tenant, expected loss)

Decisions the PRD and INTERPRETATIONS left open. Each was decided locally and
is implemented in `packages/engine/src/stages/price.ts`.

## D1 — `CommercialRatingTable.age` and `TenantRatingTable.buildingAge` bands are keyed by `yearBuilt`, not by age in years

**Decision.** The band lookup input is the building's `yearBuilt`
(`upTo: 1989` = "built 1989 or earlier"), so factors are non-increasing in
`yearBuilt`.

**Why.** `price()` receives no clock and no `asOf`, and the engine is pure
(AGENTS.md house style). An age-in-years lookup would need a reference year.
`FitRow` in `src/fit/least-squares.ts` (E15, the unit that produces the frozen
table) carries `yearBuilt`, not an age, which is the same choice on the fitting
side.

**Rejected.** Deriving a reference year from `receivedDate`/`effectiveDate`:
it makes the same table produce different premiums for the same building, and
`priceTenant` has no submission at all to read a date from.

## D2 — a missing factor input applies the neutral factor 1, and is reported

**Decision.** Unknown construction class, `yearBuilt`, protection class,
sprinkler status, contents limit or term contribute `factor: 1` with
`input: "unknown"` in the `AppliedFactor` list, rather than being imputed to a
class average or dropping the building.

**Why.** PRD 6.2/6.5: a missing value is never imputed; completeness already
penalises it. A neutral factor neither surcharges nor discounts, and the
`unknown` input keeps it visible on the console breakdown.

**Rejected.** Defaulting to the worst band (punishes the broker for a gap) and
to the best band (underprices).

## D3 — `lossHistoryFactor` is `null`, and not applied, when `fiveYearLoss` is unknown

A `null` `rollup.fiveYearLoss` means the claims were never retrieved (I-4), so
the multiplier is 1 and `lossHistoryFactor` is reported as `null`. A known
`fiveYearLoss` of `0` is a real value and picks the inclusive `upTo: 0` band.

## D4 — credibility is `1` when there is no complement to blend toward

**Decision.** `ExpectedLossDetail.credibility = n / (n + k)` whenever a
complement exists (peer mean first, book mean as the fallback, per PRD 6.7).
When both are `null`, `credibility = 1`.

**Why.** `ExpectedLossDetail` has no field for the blended number; the caller
computes `credibility × own + (1 − credibility) × complement`. If credibility
stayed at `n / (n + k)` with a `null` complement, that formula would be
undefined, and any reader reproducing it would disagree with the engine.
Full credibility on own experience is the only reading that keeps the published
detail and the published `expectedAnnualLoss` consistent.

**Rejected.** Returning `null` from `expectedAnnualLoss` when no complement
exists — it throws away the account's own measured loss history.

## D5 — protection class falls back from the building to its location

`BuildingFacts.protectionClass` wins; when absent, the building's
`locationExternalId` is resolved against `submission.locations` and that
location's `protectionClass` is used. Federato carries protection class on
`Location` (LIVE_DATA_FACTS: integers 1–10, all present), so building-level is
the enrichment and location-level is the base.

## D6 — `basis` and `estimate` on commercial

`basis = 'fitted'` and `estimate = false` exactly when the table carries a
`fitError` (i.e. it came out of `npm run rating:fit` against
`technical_premium`). A table with no fit behind it is `'table'` / `estimate:
true`. Tenant is always `'table'` / `estimate: true` (PRD 6.7: "labelled
estimate", no loss data exists).

## D7 — tenant annualization

`predictedMonthlyPremium = baseMonthlyRate × Π factors`;
`predictedPremium = predictedMonthlyPremium × 12`. The term factor is one of
the multipliers (it prices a 4-month term differently), but it does not change
the annualization divisor — `predictedPremium` is always the annualized rate,
per the `PriceBreakdown.predictedPremium` doc comment.

## D8 — tenant hazard keys are derived from the vector component keys

`hazardPortableHeater` → `portableHeater`. `priceTenant` walks
`spec.components` in index order, so the `factors` list is deterministic, and
only hazards that are both present (`x[i] >= 1`, `m[i] === 1`) and priced in
`table.hazards` are applied.

## D9 — no rounding

Premiums, rates and expected losses are returned at full float precision. The
differential comparator uses `MONEY_TOLERANCE = 1e-6`; rounding to cents here
would put the engine outside that tolerance of a naive implementation that does
not round. Formatting to dollars is `packages/contracts/src/format.ts`.
