# A14 — actions + reply routes: decisions

1. **Error envelope.** 400 `INVALID_JSON` / `INVALID_BODY` for an unparseable body;
   422 `VALIDATION` with flattened zod `issues` (`path` joined by `.`) for a bad shape
   or query. Gemini failures from the service: `LlmUnavailableError` -> 503
   `LLM_UNAVAILABLE`, any other `LlmError` -> 502 `LLM_FAILED`. Everything else is
   rethrown to `app.ts` `onError` (so a still-stubbed service keeps answering 501).

2. **`POST /actions/plan`:** an empty body means `{}` (plan every account). The
   response is the service's `ActionsPlanResponseDto`, unchanged.

3. **`GET /actions`** is served straight from `repos.actions.list` (no service exists
   for it). Newest first (the repo's order). `limit` defaults to
   `DEFAULT_PAGE_LIMIT` (200), max 500 via `actionsQuerySchema`. `externalId` and
   `insuredName` are joined from the submission row (per-request cache). Every
   optional `ActionPayload` field maps to `null` / `[]`. `sendingIsSimulated: true`
   always (PRD §16).

4. **`POST /actions/:id/approve`:** 404 `NOT_FOUND` for an unknown id; 409
   `NOT_A_DRAFT` when the stored status is not `draft` (guards a double "send").
   Otherwise returns `{ action }` from A17's `approveAction`.
   Rejected: letting the service decide re-approval — the route cannot know what
   it would do, and a second simulated send would pollute the action log.

5. **`POST /submissions/:id/reply`** accepts JSON (`ReplyRequestDto`) *and*
   `multipart/form-data` (`text`, `actionId`, `filename`, `file`). A `text/*`
   upload becomes `text`; any other upload becomes `pdfBase64`, with the upload's
   name as `filename` unless one is given. Both paths go through
   `replyRequestSchema` (exactly one of text/PDF).
   Guards, in order: unknown submission -> 404 `NOT_FOUND`; bad body -> 400/422;
   PDF over 20 MB decoded (Gemini inline ceiling) -> 413 `TOO_LARGE`; unknown
   `actionId` -> 404 `ACTION_NOT_FOUND`; `actionId` of another submission -> 422
   `ACTION_MISMATCH`; submission with no stored result -> 409 `NOT_SCORED`
   (the response's `before` is non-null, so an unscored account cannot be
   re-scored; same code A11 uses).

6. **Tests mock `services/actions` and `services/reply`** (A17 builds them in
   parallel); the route under test runs in-process against `:memory:` SQLite.
