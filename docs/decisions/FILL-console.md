# FILL-console — render the facts and the testing the backend now serves

Stage: console (`apps/console/src/**`). Built against the FILL-backend DTOs exactly as listed in
`docs/decisions/FILL-backend.md`; no DTO, API or package file was touched.

| # | Decision | Why | Rejected alternative |
| --- | --- | --- | --- |
| D1 | **The page view is chosen by `accountKind`.** `scored` keeps all twelve panels (a)–(l) exactly as before. `triage_knockout` always shows (a) explanation, (c) query trace, (k) actions; `no_policy` always shows (a), (b) score breakdown, (c), (d) as the peer benchmark alone (it has coarse peers but nothing to price) and (k). On either sparse kind, a panel whose data is actually present still shows (buildings, contradictions/interpretations, an available flip, enrichment cards, a sweep). Every panel left out is listed under "Not applicable to this account" with the reason in words; for (g) the reason is the engine's own `flip.reason`. A "Submission facts" card leads the sparse page. | Twelve cards of dashes told the reader nothing and looked broken. Listing the omitted panels with a reason keeps the page honest about what does not exist. | Rendering the empty panels collapsed inside `<details>` (still dashes once opened); hiding them silently. |
| D2 | **A detail with no `accountKind` (an API deployed before FILL-backend) maps to `scored`**, `displayLineOfBusiness` falls back to `lineOfBusiness`, `facts`/`verification` to null. | The console must not guess a kind the API never stated; the old twelve-panel view is what that API was built for. After the redeploy the field is always present. | Inferring the kind from verdict/completeness in the console. |
| D3 | **Header "Line of business" shows `displayLineOfBusiness`, never `lineOfBusiness`.** A knockout reads "Health", "Cyber", ...; a scored account reads "Commercial property". The insured name falls back to `facts.insuredName` when the DTO's top-level name is null. | `lineOfBusiness` is the scoring spec key, not the submission's line. | — |
| D4 | **Line labels: short Federato codes (`cgl`, `lpl`, any 1–3 letters) are shown upper-case as codes, never expanded;** everything else is sentence case with `tiv` kept as `TIV`. | Neither the snapshot nor the guidelines spell out `lpl`; expanding it would be an invented fact. | "Lawyers professional liability" etc. |
| D5 | **Absent facts are words, not dashes**: "Not recorded in Federato", "None recorded" (decline reason, competitor), "No underwriter assigned in Federato"; with `facts.source === 'not_fetched'` (or no facts at all) every value reads "Not read yet" and a note says they fill in on the next ingest. | Task rule: a genuinely absent fact is shown as absent, in words. | — |
| D6 | **The knockout reason names the guideline**: "Knocked out at triage: line of business is X. The carrier's appetite covers property only; every other line is Not Acceptable …", followed by the line-of-business factor's own citation from the DTO. The no-policy reason lists assessed and missing factors from the DTO's factor rows (`known`). | Every sentence traces to a DTO field or the cited guideline row. | Free-text reasons with no citation. |
| D7 | **A knockout's routing rationale reads "Not routed: a submission knocked out at triage is never routed to an underwriter."** when the API sent no routing, instead of the generic "Run the action plan". | PRD 7.6 routes only accounts that are not knocked out; the generic text sent the reader to a plan that would never route it. | Leaving the generic message. |
| D8 | **"Independent checks" is a card after the panels (and in the page index) whenever `verification` is non-null** — the 38 real property accounts, which include the 11 no-policy ones. It shows the naive implementation vs the engine row by row (verdict, score, knockouts, deciding factor), the second-opinion verdict, deciding factor and written reasoning, and a ✓ Agrees / ✗ Disagrees mark that is symbol plus word with no colour. `matchesCurrentResult: false` shows a note that the account was re-scored since. It links to `/verification`. | PRD 13: colour never carries meaning alone. Placing it after the twelve keeps a scored page "exactly as now" for (a)–(l). | Inserting it between existing panels. |
| D9 | **`/verification` is a new route** (`ROUTES.verification`, header nav "Verification", App.tsx edited as this stage's task allows) rendering `GET /verification` as the API sent it: headline tiles, the real-account checks, the per-stratum table (a null rate reads "No answered cases"), every disagreement with the engine side (verdict, score, deciding factor, knockouts, completeness, tier per factor — the engine's reasoning is its tiers) and the model side (verdict, deciding factor, written reasoning) side by side, and "What the testing found" from `defectsFound`. A null block says in words which file was not found. The Aggregate page's Verification card links to it. | Judge-facing: the whole testing story in one page, every number a DTO value. | Extending the Aggregate tiles only. |
| D10 | **The extraction reason is shown verbatim**, including "top up the Gemini credits", although text calls have moved to Claude (DECISIONS L-1). | The console never edits served text; FILL-backend flagged the staleness at its source (VERIFICATION.md). | Rewriting it in the console. |
| D11 | **Peer Verdict column** is `peers.peers[].verdict`; a null reads "No stored result". | D8 of FILL-backend; words, not a dash. | — |

Checked against real output: the knockout, no-policy and scored details produced in-process by the API
over the committed snapshot (mock adapter, fake LLM), and `verification()` on the committed files, were
mapped through the client and rendered — no panel error, no "commercial property" on the knockout page,
peer verdicts filled, 38/38 independent checks on the account pages. That check lived in the session
scratchpad and was removed.
