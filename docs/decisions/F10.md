# F10 decisions — adapt + trace recorder

1. **Adapt order: `$elemMatch` swap first, then one drop of the narrowest condition, then give up.**
   The swap loses no meaning (LIVE_DATA_FACTS: 0 rows vs 47), so it always goes first. Dropping a
   condition changes what the query answers, so it is allowed once. Rejected: repeated drops until
   rows appear — that would eventually return the unfiltered resource and call it an answer.
2. **Never widen to an unfiltered query.** `dropNarrowestFilter` returns null when the clause has one
   condition; `nextAdaptation` returns null when `where` + `filter` together hold one condition.
3. **"Narrowest" is a fixed ordinal ladder over operators**, since adapt has no row counts: literal /
   `$eq` 100 > short `$in` (95 − n, floor 55) > `$contains` 80 > two-sided range 70 > `$eq null` 60 >
   one-sided range 50 > `$exists:false` 30 > `$exists:true` 20 > `$ne`/`$nin`/`$not` 10. `$elemMatch`
   = its inner clause + 1; `$or` = its widest branch. Ties: deeper dot-path is narrower; then
   `filter` before `where`; then key order.
4. **Swap output shape** is the verified live form: `{arr: {$elemMatch: {seg: {seg: v}}}}` — nested
   objects inside, another `$elemMatch` at each deeper array boundary. Only dot-path *keys* are
   rewritten; a nested-object clause that already crosses an array is left alone. Two swapped keys
   on the same array go into `$and` (keeps "any element" semantics per condition, loses nothing).
5. **`over`.** Added (non-barrel, additive) `OVER_DECLINED_NOTE` and `declineServerAggregation()` in
   `adapt.ts`. `nextAdaptation` strips `over` from any retry and appends the note to `why`; the trace
   recorder auto-adds the note to any entry whose payload carries `over`. Since the planner never
   emits `over`, **F11 should `recorder.note(deepPassId, OVER_DECLINED_NOTE)` on the deep pass** so
   the demo beat actually appears in "How the agent got here".
6. **Trace recorder:** ids `${idPrefix ?? 'q'}-000`; `startedAt` = injected `now` + (clock − clock at
   creation); `now` absent → real wall time (federato is not the pure engine). Payload is deep-copied
   at `begin`. Errors force `totalAvailable: null`. An entry never finished is reported as
   `outcome: 'error'`, code `UNFINISHED`, rather than hidden. Unknown id / double finish throw.
   `'declined'` outcome is never produced by the recorder (TraceFinish has no field for it).
