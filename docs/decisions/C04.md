# C04 — QueuePage decisions

1. **Order is the API's.** Rows are sorted by `rank` ascending (id tiebreak) after filtering; the page never recomputes rank or quality (PRD 6.8 / INTERPRETATIONS P-6 are server-side). Rejected: re-deriving knockout ordering client-side.
2. **Out-of-appetite group.** Rows with `outOfAppetiteLine: true` go into a separate table behind a `button[aria-expanded]` labelled `Out of appetite: line of business (N)`, collapsed by default; the whole section is omitted when the (filtered) group is empty. Rejected: `<details>` — less control over the count label and the lazy table mount.
3. **Filters apply to both groups**, and filter options (lines, states, underwriters) are derived from the returned rows, not hard-coded.
4. **Search** (the `search` field of `QueueFilterValue`) matches insured name, submission id and the explanation line, case-insensitive, trimmed.
5. **Formatting.** Quality `formatScore(1 dp)`, appetite `formatScore(0 dp)`, premiums `formatMoney` as "$Q vs $P", adequacy `formatPercent` on the ratio (0.92 -> 92%), completeness `formatPercent(from: 'percent')`, null -> em dash. Pending action `titleCase`, null -> "None"; underwriter null -> "Unassigned".
6. **Navigation.** Insured cell is a real `<Link>` (keyboard reachable) and row click also navigates, both via `submissionPath` imported from the frozen `App.tsx` (circular import is safe: only a hoisted function used at render time).
7. **Test** mocks C01/C02/C03 collaborators with signature-faithful stand-ins so C04 is testable while those units are in flight.
