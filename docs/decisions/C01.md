# C01 decisions — console API client, useApi, fixtures

1. **The client maps wire DTOs to the panel view types.** `ApiClient` returns
   `panels/types.ts` views, but `@retrofit/contracts` DTOs differ in shape
   (`QueueRowDto.id` vs `submissionId`, `SubmissionDetailDto.result.*`, etc.).
   All reshaping lives privately in `client.ts`; it never computes a score,
   premium or tier. Rejected: returning DTOs cast to views (silently wrong at
   runtime).
2. **Vector labels are a private display copy of `packages/engine/vectors/*.json`.**
   The detail DTO carries no spec and `@retrofit/engine` is not a console
   dependency. Keys/labels/immovable/appetiteFactor are copied for display only;
   `scaled` is `null` (no BookStats on the wire). See requests/C01.md.
3. **Missing provenance confidence falls back to the V-7 table** (0.7 / 0.9 / 0.8)
   in contradiction sides only.
4. **Adapter `mock` is shown as `snapshot`** (HealthResponse contract).
5. **Units are passed through unconverted:** completeness and sweep coverage stay
   0..100 as the engine emits them; adequacy and shares stay ratios.
6. **`runSubmission` / `enrich` POST, then re-GET the detail**, since their
   responses are not detail DTOs.
7. **`getAggregate` joins `oneFlipAway` to the queue** to get full rows; if the
   queue call fails it falls back to minimal rows built from the aggregate.
8. **`useApiClient` is a module-level singleton** built from `VITE_API_URL`
   (default `http://localhost:3000`). No provider, because App.tsx/main.tsx are
   frozen. Tests stub `globalThis.fetch`, which the client resolves per call.
9. **`useApi` discards stale responses** (request id) and keeps the previous
   `data` while reloading.
10. **Fixtures follow INTERPRETATIONS worked cases:** FIT = B1 (84), REFER = B6
    (84, building_age refer), DNF = B2 (tiv knockout, 75), no-policy = line only
    (15, completeness 1/9, REFER by V-2). Queue adds a cyber out-of-appetite row;
    quality indices are P-5 values and ordering is P-6. The test re-derives both.
