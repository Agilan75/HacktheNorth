# E02 decisions — discover + normalize

## D1. Entity walk passes through ungrouped containers
- **Decision:** `normalize` walks through objects/arrays whose key maps to no entity group (e.g. `Policy.exposure_units[]`) without emitting them, so entities hydrated beneath them (`...exposure_units[].location.buildings[]`) are still found. Duplicates of flat records collapse on `<group>:<id>`.
- **Why:** a hydrated Policy must normalize identically to the flat records; stopping at the first ungrouped key dropped every nested building.
- **Rejected:** adding `exposure_unit` to the group vocabulary — it is a join object, not a canonical entity, and any other intermediate wrapper would hit the same bug.

## D2. Discovery vocabulary is generic, not a Federato table
- Canonical leaves plus plain-English synonyms only; normalized-name equality first, aliases second (0.9), nested paths −0.05, fuzzy guesses capped at 0.7 and never accepted (below `MIN_MAP_CONFIDENCE`). Federato field paths stay in F07's planner synonyms.

## D3. Slot values
- Agreeing sources collapse to one `Field` (first/exact source kept); disagreeing sources are all kept for the contradiction stage. Reserves are summed across indemnity + expense. Absent stays absent — no defaults invented. State codes trimmed upper (G-7), construction lower snake (G-8).
