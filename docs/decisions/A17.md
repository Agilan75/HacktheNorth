# A17 — actions-plan service + reply service

## D1 — Plan scope
Every scored `commercial_property` row, narrowed by `externalIds` when given. Tenant
rows (sweeps) have no broker or underwriter and are out of scope. Unscored rows count as `skipped`.

## D2 — Route = not knocked out by the engine
PRD 7.6 "any account that is not knocked out" is read as `result.evaluate.knockout === false`
(triage knockouts are never stored). Inputs: `result.rollup.primaryState` (I-1) and
`canonical.exposure.requestedLimit`, falling back to `Submission.requested_limit` from the adapter.
`routed` counts assigned accounts; `needsSeniorReferral` counts the rest. They do not overlap.

## D3 — Directory from the adapter
Underwriter, Broker, Contact and the account's Submission rows come from 4 read queries through
`deps.adapter`, run once per plan. Failure does not fail the plan: every account is flagged for senior
referral with a note, and drafts greet "Hello,". Rejected: reading `raw` bundles (their shape depends on
which planner pass fetched the account).

## D4 — Idempotent re-plan
The latest `route` row and the open `draft` request of an account are updated in place. A request already
`approved`/`sent` with the same field paths is not drafted again (counted `skipped`, returned as is).
A request answered (`replied`) can be followed by a new one.

## D5 — Draft authorship
`draftRequestCall` (A06) → F13 `validateDraft`. A Gemini draft that fails F13's check is replaced by
`templateDraft`. `actor` = `gemini:draft-request` only when the stored text is not the template. Any
`LlmError`, including `LlmUnavailableError`, falls back to the template per account with a note, so one
missing key never fails a 38-account plan. Rejected: rethrowing for a 503 (it would leave a half-written plan).
`draftsOff` stores the fields with `draft: null`.
Observed upstream: F13's draft check flags A06's own template line "state for each location" as asking
for `headquartersState`. It shows up only as a note; not A17's to fix.

## D6 — Approve
`draft` → `sent` (PRD: "approve marks a request sent"), note says nothing is emailed. Not a draft → throws.

## D7 — Reply: which fields
`actionId`'s fields; else the latest `sent`/`approved` request, else the latest request; else what
`selectRequest` would ask for today. Extract-reply field types come from a private leaf table
(year/money/percent/boolean/number, construction options = the 8 live values).

## D8 — Reply: gate and PDF
A06 extracts, F13 `validateExtraction` is the gate. With a PDF, a value whose only fault is
`quote_not_found` (code cannot read the PDF) becomes `needsConfirmation`. It is never accepted.

## D9 — Reply: apply and persist
Accepted values → F13 `applyReply` → engine `merge(canonical, [], [], answers)` → stored `canonical`
(A16 D1: whatever must survive a later `rescoreBook` belongs in canonical) → `rescoreOne`. Nothing accepted
→ no re-score, `after = before`. Wildcard / `rollup.*` paths are dropped by merge (F13 D-4 known limit).
`newContradictions` = open contradictions in the new result that are new by id or on a path F13 reports as conflicting.

## D10 — Log
One `reply` action (`applied` if anything was accepted, else `replied`), with every extracted value,
before/after and ranks. One `rescore` action when the engine re-ran. The answered request → `replied`.
`ReplyResponseDto.id` = the submission id.
