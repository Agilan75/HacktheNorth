# M1 — Mobile API client + offline sweep queue

Files: `apps/mobile/src/lib/api.ts`, `apps/mobile/src/lib/queue.ts`, and their `*.test.ts` (40 tests, node).

## Decisions

| # | Decision | Why | Rejected |
|---|---|---|---|
| M1-1 | Paths are `src/lib/api.ts` / `src/lib/queue.ts` (task prompt), not `src/api/client.ts` / `src/api/queue.ts` (UNITS.json). | The task prompt wins on *what*, and the other Run 3 mobile units were told `@/lib/api`. | Following UNITS.json and orphaning every import. |
| M1-2 | Route paths are mirrored in `API_PATHS`, not built with `routePath()`. A test pins every one to `ROUTES` in `@retrofit/contracts`. | R3-4: contracts is type-only in the bundle. A runtime import would pull zod and the engine into Metro. | A runtime import of `routePath`. |
| M1-3 | Retries: 4 attempts, 500 ms base, x2, capped at 8 s, 50% equal jitter. Retried: network error, our own timeout, 408, 429, 5xx. Never retried: other 4xx, parse errors, caller aborts, missing config. | PRD 11 "retry with backoff". A 4xx will fail the same way on every retry. | Retrying everything, or a fixed delay. |
| M1-4 | Timeouts: 15 s per attempt, 60 s for image uploads (POST /sweeps, verify-fix). | Up to 15 base64 JPEGs on hotel/venue Wi-Fi. | One 15 s deadline for all calls. |
| M1-5 | Only `network`/`timeout` errors count as "offline" and go into the queue. A 5xx that survives the client's retries, or a 4xx, returns `{status:'failed'}` for the screen to show. | "Queued, will send when you are back online" must be true. A server bug isn't an offline problem. | Queueing on any failure. |
| M1-6 | The queue is **in memory only**. It waits indefinitely (2 s base, x2, capped at 60 s, 30% jitter), sends oldest first, and one offline failure pushes every due item back so a dead connection costs one request per tick. `retryNow()` exists for the app-foreground or "Try now" hooks. | Task said in memory. No NetInfo package is installed and none may be added, so there's no connectivity event, only the timer and manual retry. | AsyncStorage persistence (not installed). |
| M1-7 | Retrying POST /sweeps and /answers after a 5xx can in theory double-submit. Accepted. | The API creates the sweep then answers 201, so a 5xx after creation is unlikely. The request DTO has no idempotency key and the DTOs are frozen. | Not retrying POSTs, which contradicts PRD 11. |
| M1-8 | `EXPO_PUBLIC_API_URL` is read with the literal static `process.env.EXPO_PUBLIC_API_URL` inside `readApiUrlFromEnv()`. If it's missing, every call fails fast with kind `config` and a plain-language message. There is no localhost default. | Expo inlines only static accesses. `localhost` on a phone points at the phone, which fails silently. | Defaulting to `http://localhost:3000`. |
| M1-9 | Also exported: `getShare` (GET /s/:slug for `/s/[slug]`), `pollSweep` (for `/analyzing`, stops at `questions`/`done`/`failed`, 1.2 s interval, 3 min limit), `describeApiError` / `queueStatusMessage` (plain-language strings, never a status code), and the shared singletons `getApi()` / `getSweepQueue(send)`. | Screens need them. Writing them once here keeps the retry and wording consistent. | Each screen writing its own. |

## Usage for the screen units

```ts
import { getApi, pollSweep, describeApiError } from '@/lib/api';
import { getSweepQueue, queueStatusMessage } from '@/lib/queue';
const queue = getSweepQueue((req) => getApi().createSweep(req));
const r = await queue.submit(body); // 'sent' | 'queued' (show r.message) | 'failed' (show r.message)
if (r.status === 'queued') queue.waitFor(r.queueId).then((sweep) => router.replace(...));
```

## Human checklist (iPhone, Expo Go)

1. **Base URL.** Set `EXPO_PUBLIC_API_URL` to the Mac's LAN IP (e.g. `http://192.168.x.y:3000`, not localhost) and restart Metro with `-c`. Do a sweep. It worked if `/analyzing` shows real stages and the API log shows `POST /sweeps`.
2. **Missing URL.** Unset it and restart. Starting a sweep should show "The app is not connected to a server…" rather than hanging or crashing.
3. **Offline queue.** Capture a sweep, turn on Airplane Mode, tap Finish. The app should say "Queued. Your sweep will send when you are back online." within about 5 s (4 quick tries). Turn Airplane Mode off. The sweep should send within about 60 s, or right away if the screen calls `retryNow()` on foreground, and move on to `/analyzing`.
4. **Retry on 5xx.** Stop the API for about 3 s during `/analyzing` polling and start it again. Polling should recover on its own with no error screen.
5. **Large upload.** A 15-frame sweep on normal Wi-Fi should finish without a timeout error (60 s per-attempt limit).
6. **Queue lifetime.** Kill the app while a sweep is queued. The sweep is lost, which is expected (M1-6). Confirm nothing crashes on relaunch.
