# E04 — merge + contradict

Six things the PRD and INTERPRETATIONS left open. Decided here, per AGENTS.md §8.

## D1 — Append order is the precedence contract

`merge` appends in a fixed order: values already present (broker,
`self_reported`), then `enrichment`, then sweep observations, then `answers`.
Nothing is overwritten (PRD 6.2), so precedence only ever matters as the
insertion-order tiebreak `bestValue` (E01) applies after confidence and source
order. Answers go last because a reply to a targeted question is the most recent
correction of that slot.

Rejected: sorting by confidence at merge time. That would reorder the slot, and
`types.ts` states merge "appends, it never reorders or removes".

## D2 — Missing values are dropped, not appended

A value that is `null`, `undefined` or `NaN` is missing (INTERPRETATIONS G-1),
so `merge` drops it. Appending it would manufacture a fake competing value at
stage 5 and make an unavailable enrichment plugin look like a contradiction.

## D3 — An unresolvable canonical path is dropped silently

`merge` writes only into slots the submission already has: a known leaf on a
known group, or a list entry found by `externalId` (`buildings.B3.yearBuilt`),
or a coverage line found by `code`. `buildings.B9.tiv` on a submission with no
B9 is dropped. The engine is pure, so it cannot log; inventing the building
instead would corrupt every TIV-weighted share downstream. Both
`hazards.<key>` (the PRD's spelling) and `hazards.present.<key>` resolve to the
same slot.

## D4 — merge does the minimum with observations, and does not duplicate E12

E12 (`sweep/observations.ts`) owns dedupe, self-consistency, negative evidence
and the pair rules, and it needs a `CoverageResult` that `merge`'s signature
does not carry. So `merge` only turns the observation list it is handed into
hazard values: presence for the seven labels whose sighting *is* the hazard
(`portableHeater`, `extensionCord`, `candle`, `stove`, `blockedExit`,
`windowAcUnit`, `waterHeater`), counts for `smokeDetectorCount`,
`sprinklerHeadCount` and `highValueContents`, and `ceilingObserved = true` when
some observation saw the ceiling. Relational keys (`heaterNearCombustible`,
`powerBarOverload`) and the *negative* `ceilingObserved = false` are E12's and
arrive here as ordinary `ExternalValue`s. Presence keeps the highest-confidence
sighting; a count keeps the highest confidence among its contributors, matching
the sweep's own "merge, keeping max confidence" (PRD 9.3 step 3).

Observations below `MIN_OBSERVATION_CONFIDENCE` are still merged. The gate in
PRD 9.3 step 7 is about what the VOI loop asks the user to confirm, not about
what the slot holds, and the low confidence already travels on the provenance.

## D5 — merge carries `rollup` through untouched

`merge` does no arithmetic, so it neither recomputes nor deletes `rollup`.
**The composer (E16) must re-run stage 3 after a merge that wrote a
rollup-feeding path** (`buildings.*`, `locations.*`, `history.*`,
`receivedDate`), or the derived numbers are stale.

Rejected: stripping `rollup` on such a merge. It would be safer against staleness
but would hand `undefined` to any caller that runs rollup → merge → vectorize,
turning every component missing — a far worse failure across unit boundaries.

## D6 — Contradiction severity is binary, and equality is tolerant

PRD 6.3 says "HIGH if a rule depends on it"; the E04 scope says HIGH/LOW. So:
HIGH when at least one rule — Federato's or a Retrofit extension — reads a field
the disputed path feeds, LOW otherwise. `MEDIUM` is never emitted by stage 5.
The path→rule-field bridge is a private table in `contradict.ts` (rules address
vector component keys and rollup fields, contradictions live on raw canonical
paths); a `rollup.` prefix on the rule field is stripped before the lookup.

Two values conflict only when materially different: numbers within
`MONEY_TOLERANCE` (1e-6) agree, so float noise is not a contradiction, and
strings compare trimmed and case-folded, so `"OH"` and `" oh "` agree. Every
contradiction is returned `open` — stage 5 detects, it never resolves — with id
`contradiction:<canonicalPath>`, and the list is sorted by canonical path so it
is deterministic.
