# M9: /hazard/[id], /s/[slug], and the 3-photo path

Files: `apps/mobile/app/hazard/[id].tsx`, `apps/mobile/app/s/[slug].tsx`, `apps/mobile/src/lib/photos.ts`, `apps/mobile/src/lib/photos.test.ts` (25 tests, node).

## Decisions

| # | Decision | Why | Rejected |
|---|---|---|---|
| M9-1 | **The hazard close-up is cropped on the phone** with `expo-image-manipulator`, using `cropRect()` in `photos.ts`. It uses the same geometry as the API's `cropToBox`: box_2d `[y0,x0,y1,x1]` in 0..1000, 15% padding, clamped, and never empty. | `apps/api/src/images/crop.ts` exists, but no route serves it. `SweepDto` only carries the whole frame (`frames[i].imageRef`, a data URL) plus `observations[i].box2d`. Cropping is presentation, not a number. | A contract request for a crop route, which would block the screen. |
| M9-2 | **If the crop fails, the whole frame is shown with the box drawn on it** as a double outline (paper outside, ink inside), and a "Show the whole photo" / "Show the close-up" toggle. | A shape stays visible on light and dark photos, and the item is still identified by colour-blind users. | Showing no photo at all when the crop fails. |
| M9-3 | **`/hazard/[id]` accepts any spelling of the hazard.** That covers the key (`candle`), `hazards.present.candle`, `hazards.candle`, `hazardCandle` (vector component), `hazard.candle` (price factor), `hazard_candle` (rule factor), or an observation id. Optional query params: `?sweep=<id>` (defaults to the session's sweepId) and `?obs=<observationId>` (which sighting to show). | M8 (/verdict) is written at the same time and I cannot see which id it links with. `hazardKeyFromId` is tested on every spelling. | Picking one spelling and hoping M8 matches it. |
| M9-4 | **Which photo:** first the observation named in the route, then the observations the API cited in the hazard's provenance (`observation:`, `observations:`, `relate:a+b`), then any sighting of a matching object. Within each of those, the primary object wins (the heater, not the curtain), then an observation with a box, then higher confidence. Frames that were dropped or have no `imageRef`, and pair-rule `derived` items, are never used. | The photo should show the actual evidence the engine used. | Always taking the highest-confidence sighting. |
| M9-5 | **"If fixed → verdict X, price Y" comes only from the engine's flip** (`result.flip.flip`). It is shown only when a move's `componentKey` is this hazard's component (`hazard<Key>`). When the flip needs a second move too, the screen says so. Otherwise the screen says fixing this alone isn't the change that gets a quote (or that the quote already fits), and offers **"I fixed it: check with a new photo"** → `/verify-fix?hazard=<key>&sweep=<id>`. verify-fix re-prices with the API's real before/after. | PRD invariant: no client decides a number. The API returns no per-hazard what-if, and dividing the price by the hazard factor would be computing a price. | Computing `premium / factor` on the phone. |
| M9-6 | Flip premiums are labelled **"a year"** (`premiumBefore`/`premiumAfter` are on the `predictedPremium` scale, which is annualized for tenant). The current tenant price elsewhere is `predictedMonthlyPremium` "a month". The hazard price factor is shown as the API's multiplier ("multiplied by 1.10"), with no conversion to a percentage. | Show the API's numbers without doing arithmetic on them. | Converting annual to monthly on the phone. |
| M9-7 | **"Why it matters"** is a fixed plain-language sentence per hazard (`HAZARD_WORDS`), plus the insurer's own rule quote when the API reports a fired rule whose condition is this component. The fix text is the flip move's `fixHint` when there is one, and otherwise a fixed sentence. | Plain language comes first (PRD 11), and the quote shows where the rule comes from. | Showing only the rulebook quote, which reads like underwriting text. |
| M9-8 | **The 3-photo path** is in `photos.ts`. There are exactly 3 slots, and slot i gets `PHOTO_BEARINGS[i]` = `uploadBearings(3)` = 0/120/240 (M2's helper, not re-implemented). Photos come from the library (`pickPhotosFromLibrary`, ordered multi-select, up to 3) **or** from the camera one at a time (`takePhotoWithCamera`), so someone who can take a photo but cannot do a steady 360° sweep has a path too. Each photo is downscaled to at most 1600 px on its long edge, as JPEG q0.7 base64. `commitPhotosToSession(slots)` does `sessionStore.setFrames(frames, 'upload')`, and after that the session goes through `buildCreateRequest` → POST /sweeps, exactly like a sweep. | PRD 11. The same pipeline, so the uploaded photos pass the same quality gate and get the same verdict. | Letting the user send 1 or 2 photos, which leaves coverage too thin to be useful. |
| M9-9 | `photos.ts` loads `expo-image-picker` / `expo-image-manipulator` with **dynamic `import()`** inside the native functions. | Importing the file under vitest (node) then never touches React Native. Metro turns `import()` into a normal require when bundling. | Splitting the native half into a file M9 doesn't own. |
| M9-10 | `photos.ts` also holds the pure hazard-photo lookup (`hazardKeyFromId`, `findHazardPhoto`, `hazardStatus`, `cropRect`, `bearingWords`). | It is "which photo to show" logic, it needs tests, and `photos.ts` is the only lib file M9 owns. | Putting it untested inside the screen. |
| M9-11 | `/s/[slug]` shows tenant verdicts in plain words ("We can quote this") and commercial ones with the kit's underwriting labels. It also shows the price, an "estimate" flag, the API's appetite score rounded for display, the explanation, the deciding rule with its quote, and the flip moves with their fix hints. **Share** uses the RN `Share` sheet with `Linking.createURL('/s/<slug>')`. A 404 gets "link wrong or out of date" and no retry; a 409 (NOT_SCORED) gets "not ready yet" and a retry. | Plain language, and every number comes from the API. | — |

## For other units

- **M8 (/verdict, /verify-fix):** link a hazard with `router.push({ pathname: '/hazard/[id]', params: { id: hazardKey } })`. Any spelling from M9-3 works. The hazard screen's "I fixed it" button pushes `/verify-fix` with params `hazard` (the hazard key, the same value as `VerifyFixRequestDto.hazardKey`) and `sweep`.
- **M5/M6 (the "Use photos instead" path):** `import { emptySlots, placePhotos, setSlot, nextEmptySlot, slotsStatusText, PHOTO_STEPS, pickPhotosFromLibrary, takePhotoWithCamera, commitPhotosToSession } from '@/lib/photos'`. Pick → `placePhotos(slots, outcome.photos)` → when `nextEmptySlot(slots) === null`, call `commitPhotosToSession(slots)` → send the session the same way as a finished sweep. **Nobody owns a photo-upload screen yet.** The functions are here; the screen that calls them belongs to whoever owns /new or /sweep.

## Human checklist (iPhone, Expo Go)

Nothing below has been run on a device.

1. **Close-up crop.** Do a sweep with a candle or extension cord in view, then open it from /verdict (or go to `/hazard/candle`). Pass: the photo is zoomed onto the item, not the whole wall. Tap "Show the whole photo". Pass: the full frame appears with a box around the item, and the box sits on the item (not shifted or rotated). If the box is off, the frame's orientation differs from what Gemini saw. Report which way it is off.
2. **Crop fallback.** If the close-up never appears (skeleton stays, or whole photo with no toggle), `ImageManipulator.manipulate(<data URL>)` isn't working in Expo Go. The fallback still shows the full photo. Log it as a decision.
3. **"If you fix this".** For a hazard the verdict screen names as the fix: the card shows a verdict pill with words and a glyph, plus "about $X a year, instead of $Y now". Those numbers must match the console's flip for the same sweep. For a hazard that is not the fix: the card says fixing it alone is not the change that gets a quote, with no invented numbers.
4. **Verify from here.** Tap "I fixed it: check with a new photo". Pass: /verify-fix opens for that hazard. This depends on M8 reading the `hazard` param.
5. **Share link.** Open `retrofit://s/<slug>`, or `exp://…/--/s/<slug>` in Expo Go, for a known slug. Pass: the verdict, price, "Why", the rule quote and the change list all appear. Tap Share. Pass: the iOS share sheet opens with a message and a link. An unknown slug shows "We could not find this shared result" and no Try again button.
6. **3-photo path, library.** Call `pickPhotosFromLibrary()` from the upload screen and pick 3 photos in a chosen order. Pass: the picker shows order numbers, and the request carries bearings 0, 120, 240 in that order. Each image is ≤1600 px (check the API log or the frame size) and the room reaches a verdict.
7. **3-photo path, camera.** Call `takePhotoWithCamera()` three times. Pass: the system camera opens each time and all three slots fill. Deny camera permission. Pass: the message suggests the library instead, and the app doesn't crash.
8. **VoiceOver.** On /hazard and /s: every photo is announced as an image with a sentence ("Close-up photo of the open-flame candle…"), buttons are announced as buttons, headings as headings, the status reads "Found. We saw this…", and the verdict reads its words, not a colour.
9. **Largest text (Settings → Accessibility → Larger Text, max).** Pass: nothing is clipped, buttons grow taller, the screen scrolls, and the footer buttons remain reachable.
10. **Grayscale (Settings → Accessibility → Display → Color Filters → Grayscale).** Pass: the "Found / Fixed / OK" status, the verdict pills and the box around the item are all still distinguishable.
