# F04 decisions — mock pipeline (expand / unwind / over / select / sort / pagination)

Source: QUERY_REQUEST_BODY.pdf, LIVE_DATA_FACTS.md. Each entry: decision / why / rejected alternative.

1. **Reference index is the live schema, transcribed.** `buildReferenceIndex` returns a static table of all
   reference fields in `docs/federato/live-schema.json` (incl. nested `Policy.producer.broker|contact`,
   `ExposureUnit.underlying_layer.policy`). The `store` argument is unused. Why: references must not be guessed
   from data shapes. Rejected: inferring references from numeric fields in the store.
2. **Expand of a missing id**: `one` → `null`, `many` → the id is dropped. Already-hydrated objects pass through.
   Expand keys that are absent on the record or not references/objects are ignored (lenient), not an error.
3. **Unwind default type is `inner`** (Mongo semantics; PDF shows bare strings as fan-out). `left` keeps an empty
   array's parent with the path set to `null`, and keeps null/missing parents unchanged. A non-array value is
   treated as a one-element array. Entries apply in order, so `exposure_units.location.buildings` works after
   `exposure_units`.
4. **`over` is implemented per the PDF** (mock-only; the planner never emits it). It defaults to `['id']` **only
   when `select` holds a reduction**; with neither it is a no-op. This makes reductions without `over` behave like
   the PDF's auto-fleet example (unwound rows fold back per policy) and yields `$count = 1` per un-unwound row,
   matching what the live handler returns. Groups are first-seen order; group rows ride on a non-enumerable symbol
   so they never serialise. When `payload.over` is given, `QueryResult.groups` is set **and** `results` holds the
   same array (`results` is required by the frozen type); `total` is the group count (PDF example: `total: 2`).
   With `over` but no `select`, each group projects its `over` keys.
5. **Reduction paths are absolute from the pipeline row and cross arrays** (fan-out collect), so
   `{ $sum: 'exposure_units.basis_amount' }` sums a row's units without unwind (PDF projection example). Plain
   projection paths still do not cross arrays except by mapping a nested select over array elements.
   `$countDistinct` with an array of paths counts distinct tuples, skipping tuples with any null.
   `$min`/`$max` compare numbers, then strings, then booleans.
6. **Selecting a missing field yields `null`**, not an absent key ("missing is null" in the fixture/API shape).
   Dot-path keys and the array form normalise to one nested select object; `true` wins a merge conflict.
7. **`applySelect` has no resource argument** (frozen signature), so a `$expand` leaf called through it resolves a
   path against every resource and accepts it only if all candidates share one target. `runPipeline` passes the
   real resource privately.
8. **Sort**: stable; nulls/missing/NaN last in both directions; mixed types order numbers < strings < booleans.
9. **Pagination**: no `limit` → all rows; negative/fractional values are floored and clamped at 0. `total` is the
   row count after sort, before pagination.
