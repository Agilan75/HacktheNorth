# A07 decisions — enrichment HTTP helper, Nominatim geocode, flood zone

| # | Decision | Reason | Rejected |
|---|---|---|---|
| A07-1 | Flood zones come from FEMA's National Flood Hazard Layer polygons (`S_Fld_Haz_Ar`, fields `FLD_ZONE`, `ZONE_SUBTY`, `SFHA_TF`) via an ArcGIS point-intersect query, not from the OpenFEMA `/api/open` datasets. Source id stays `openfema_flood`. | OpenFEMA's datasets have no point-in-polygon flood zone lookup; the NFIP policy dataset only gives zones at ~11 km rounded coordinates. NFHL is FEMA's public source for a building's zone. | Nearest NFIP policies from `FimaNfipPolicies` (imprecise). |
| A07-2 | Two endpoints tried in order: `hazards.fema.gov/.../NFHL/MapServer/28` then Esri's hosted NFHL copy `services.arcgis.com/P3ePLMYs2RVChkJx/.../USA_Flood_Hazard_Reduced_Set_gdb/FeatureServer/0` (same field names, verified live: Miami 25.7657,-80.1936 → `AE`, `SFHA_TF: 'T'`). The 6 s budget is split 3 s + 3 s so one location never exceeds 6 s. | Measured 2026-09-19: hazards.fema.gov and msc.fema.gov reset every TLS connection from this network; the mirror answered in ~200 ms. | NFHL only (flood card would be permanently unavailable on this network); mirror only (loses the primary source). |
| A07-3 | When a point touches several polygons, keep the most hazardous: V* > A* / SFHA > D > shaded X (0.2 %) > X. `AREA NOT INCLUDED`, `OPEN WATER` and blank are "not mapped": the card says so and no value is written. | A point on a boundary must not be reported as the safer side. | First feature returned. |
| A07-4 | Card is `available` when at least one location's lookup succeeded; per-location failures show as "Unavailable (reason)" fields. All failed → `available: false`, `unavailableReason` = the distinct error strings joined by `; `, no fields. No locations → "No locations on this submission". The plugin never throws. | PRD §8 "unavailable card on failure", without hiding partial success. | Whole card unavailable on any failure. |
| A07-5 | Writes only `locations.<externalId>.floodZone` (declared as `locations[].floodZone`) with provenance `{ source: 'enrichment', sourceDetail: 'openfema_flood: FEMA NFHL S_Fld_Haz_Ar (<endpoint id>)', observedAt: nowIso }`; confidence omitted so the SOURCE_CONFIDENCE table (0.9) applies. Geocoded coordinates are **not** written as values. | Fire-station plugin geocodes the same locations; writing lat/lng from two plugins would create duplicate competing values. | Writing `latitude`/`longitude` too. |
| A07-6 | `fetchJson`: timeout covers response and body; also races the abort so a fetch that ignores `signal` still times out. Errors are short card-ready strings: `timeout after N ms`, `HTTP <status>`, `invalid JSON`, `aborted`. Failures are never cached. Cache TTL 24 h, measured only when the caller passes `nowMs` (derived from `context.nowIso`); without `nowMs` an entry lives for the process. No wall-clock read. | A01-6: no clock outside `Deps.clock`. | `Date.now()` TTL. |
| A07-7 | Caches are module-level, one per source (`geocode.ts`, `flood.ts`), so they survive the runner building fresh plugin instances per run. The flood cache stores the parsed zone, not the body, because ArcGIS error envelopes arrive as HTTP 200. | Per-source cache (PRD §8). | Cache per plugin instance. |
| A07-8 | `geocode()` returns existing coordinates with no request; treats `(0, 0)` as missing; returns `null` (no request) without a street address or ZIP (a city/state centroid is miles off); sends `format=jsonv2&limit=1&countrycodes=us` with User-Agent `Retrofit/0.1 (...)`; serialises live requests with a 1.1 s gap (Nominatim policy: ≤1 req/s); throws on HTTP/network failure. | Nominatim usage policy; a wrong point is worse than no point. | Geocoding city-only locations. |
| A07-9 | `durationMs` uses `performance.now()` (monotonic interval timer, not the wall clock). | Plugins must report duration; the context only carries `nowIso`. | Leaving it 0 for the runner to fill. |
