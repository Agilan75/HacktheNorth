# E08 — decisions (flipBounds + flip)

Unit E08 owns `packages/engine/src/stages/flip.ts` (+ colocated `flip.test.ts`).
F-1..F-6 and V-9 are implemented literally. Open points decided here:

## D-1 — "failing" is judged by the factor tier, not only by interval membership
A component is unsatisfied when it is missing, or when it lies outside every
non-refusing interval that names it AND its factor tier (`vector.t`, T-SPAN) is 0.
Reason: `pctTivPost2010` is named only by AG-AGE-T, so pure interval membership
reported it failing on every Acceptable building-age account, polluting
`blockedByImmovable`. Rejected: interval membership alone.

## D-2 — interval choice inside one component uses raw distance
`flipBounds` has no `BookStats`; with none, every `log_minmax` component scales
to 0 and all candidate intervals tie (Target won, so premium 40k proposed 75k,
contradicting F-5's 50k). Raw distance orders same-side landings identically to
any monotone scaling. F-4's scaled Euclidean length still decides across
components in `flip`. Ties: Target interval preferred.

## D-3 — `flip` keeps the chosen interval's inclusivity
`FlipBound` (frozen) has no inclusive flags, so `flip` resolves bounds through a
private function that returns the interval too. An exclusive boundary lands one
representable step past it (F-5) instead of on it.

## D-4 — supplying a missing movable component costs scaled length 1
A missing value has no scaled position; 1 is the full range, so supplying data
never looks cheaper than a real move. Label: "Supply <label>: <value>".

## D-5 — no BookStats means zero-length currency moves
With `bookStats = null`, `log_minmax`/`log1p_minmax` moves scale to 0 (E05's
`scaleVector` behaviour). Accepted: degenerate, deterministic, and the verdict
gate (F-6) is unaffected.

## D-6 — pricing failure never fails flip
`premiumBefore`/`premiumAfter` are `null` when `price` throws or returns a
non-finite value.
