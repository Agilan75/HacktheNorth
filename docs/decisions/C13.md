# C13 decisions — RulesPage, GlossaryPage, Tooltip

1. **Rulebook shape.** `ApiClient.getRules()` (C01) returns `rulebooks: unknown[]` and drops the DTO's
   `interpretations` and `weights`. RulesPage narrows each rulebook to `RulesResponseDto['rulebooks'][number]`
   with a local guard and drops malformed rules instead of crashing. Weight is read from `rule.weight`
   (every appetite rule carries it); the factor heading shows it when all rules of that factor agree.
   Rejected: a contract request to widen `RulesResponse` — the per-rule data already covers PRD §10.
   Follow-up for C01's owner if wanted: pass `interpretations` through so the page can list applied interpretations.
2. **Extension grouping.** A rulebook is an extension group when `isExtension` is true or its id is `extensions`;
   a rule with `extension: true` inside any other rulebook is moved into the same group. The group is titled
   "Retrofit extension rules (ours, not Federato's)" and never shows a weight.
3. **Factor order.** The eight appetite factors follow the PRD §6.6 table order; any other factor follows in file order.
4. **Tooltip data.** One `getGlossary()` per ApiClient, cached in a module-private WeakMap; a rejected request is
   evicted so the next mount retries. Term matching is case-, space-, hyphen- and underscore-insensitive and
   accepts a trailing plural `s`. Aliases are not available (client drops them).
5. **Tooltip accessibility.** The trigger is a `tabIndex=0` span with `aria-describedby` pointing at a
   `role="tooltip"` element that is always in the DOM (visually hidden when closed). Opens on hover or focus,
   closes on blur, mouse leave or Escape.
6. **Tests.** Colocated `*.test.tsx` files beside the three owned files (same convention as C03's Filters.test.tsx).
