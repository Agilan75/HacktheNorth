# C06 decisions — Explanation (a) + ScoreBreakdown (b)

1. **Score total is the `appetiteScore` prop, never a re-sum of `factors[].points`.** PRD 10 house rule: no panel recomputes a score. Rejected: summing rows as the footer total (would drift from the engine on any rounding or extension-rule difference).
2. **`points` is rendered as-is at one decimal**, read as `100 × weight × tierValue` (engine `FiredRule.points`). Weight printed at two decimals (`0.15`), tier value at one (`0.6`, `1.0`). Rejected: weight as a percent (`15%`), which reads like a share of TIV.
3. **Scales:** `completeness` is 0–100 (INTERPRETATIONS V-6, `formatPercent from:'percent'`); `confidence` is 0–1 (V-7, `from:'ratio'`).
4. **A missing factor prints the word "Missing" and 0.0 points** (G-2); a knockout prints its tier word plus a "Knockout" badge (G-3, B12: score not zeroed). Colour never carries meaning alone.
5. **Explanation uses the top-level `verdict` prop for the pill**, not `explanation.verdict`, so the pill always matches the queue row. Deciding factor is shown as the pill detail; `decidingFactorId === null` prints "None: every appetite factor is missing" (V-8 c).
6. **Styles are inline from `@retrofit/design` tokens** because `base.css` is owned by C02. Factor table reuses `DataTable` (sortable, accessible caption).
7. Tests are colocated `*.test.tsx` siblings, covered by the OWNERSHIP rule "a path mapped to a module also covers its colocated test". Test data is built inline because `fixtures/dto.ts` (C01) is still a stub in Run 1.
