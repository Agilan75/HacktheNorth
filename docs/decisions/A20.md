# A20 decisions — `npm run seed`

| # | Decision | Reason | Rejected |
|---|---|---|---|
| A20-1 | `seed.ts` exports `runSeed(deps, options)` beside the frozen `main()`; `main` only builds real `Deps` (env -> db -> migrate -> adapter -> Gemini provider -> system clock) and auto-runs only when the file is the process entry (same guard as `index.ts`). | Testable in-process against `:memory:` with the mock adapter, fake LLM and fake plugins. `main()` keeps its frozen signature. | Importing `buildDeps` from `index.ts` (its DbHandle is module-private, so the seed could not migrate or close). |
| A20-2 | Order: `ingestFederato(deps, { force })` -> enrichment for every normalized submission with >= 1 location -> one `rescoreBook` -> seeded sweep. | `rescoreBook` reads enrichment values back from the `enrichments` table, so one book-wide pass after all enrichment gives consistent BookStats, peers and rank; per-account `rescoreOne` would be O(n^2) and rank against a half-enriched book. | Calling `POST /enrich/:id` logic per row with `rescoreOne`. |
| A20-3 | Enrichment rows use the exact id/payload shape of `routes/run.ts` (`<submissionId>:<source>`, `{ card, values, raw, unavailableReason, durationMs }`), copied privately. | Rescore and the run route both read that shape; `locationsOf`/`persistOutcomes` are private in run.ts and HELPERS.md forbids new shared helpers. | A shared enrichment-persistence helper. |
| A20-4 | Idempotent enrichment: a submission is re-fetched only if some source has no available row; `--force` re-fetches everything. Concurrency 2 submissions at a time. | Re-seeding should not hammer OpenFEMA/Overpass; failed sources get retried. Public Overpass allows ~2 slots per client (A08-3). | Always re-fetching; unbounded parallelism. |
| A20-5 | Seeded sweep stored under fixed id `sweep_seed_bedroom` (exported `SEEDED_SWEEP_ID`), 15 frames at 24-degree steps with no image, A10's observations, coverage from `coverage(bearings, FRAME_FOV_DEG)`, inserted at stage `observing` and advanced with `advanceSweep` (relate -> score -> questions). Left alone on re-seed unless `--force` or it failed. | Skips quality gate and observe (no images), keeps the real pipeline for the rest. The fixed id makes re-seeding update, not duplicate. | Minting a random id per seed. |
| A20-6 | If `relate` fails (no `GEMINI_API_KEY`, overload), the sweep is reset to `relating` with the seeded observations and scored on the engine's pair rules alone. | PRD 9.1: with the key unset the API still serves the seeded sweep; pair rules run in code, relate only adds/adjusts. | Leaving the sweep `failed`. |
| A20-7 | The seed does not run `POST /actions/plan`. | Scope is "ingest and enrich everything"; planning drafts ~dozens of Gemini `draft-request` calls and belongs to the demo step that approves a request. | Planning actions during seed. |
| A20-8 | CLI flags: `--force`, `--no-enrich` (offline seed), `--no-sweep`. | Offline fallback for the demo without network. | — |
