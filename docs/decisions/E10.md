# E10 — peers + quality index + rank: decisions

## 1. Coarse match uses `stateTier` and `totalTiv` only
PRD 6.5 names requested limit, insured revenue and HQ state for the reduced vector.
The commercial vector spec carries no revenue component, so the reduced set is
`stateTier` (index 2) and `totalTiv` (index 3, standing in for requested limit).
An account is matched coarsely when every peer component (2..10) outside that set
is missing. Rejected: adding revenue as a side-channel distance term — it would
make the distance diverge from P-1 and from the naive implementation.

## 2. A peer is labelled coarse when either side is coarse
`PeerMatch.coarse = candidate.coarse || self is coarse`.

## 3. Dropped quality terms report 0 in `QualityComponents`
P-5 drops a null term and renormalizes the remaining weights. `QualityComponents`
is non-nullable, so a dropped term is reported as `0` there; it never enters the
index. The raw nullable adequacy is on `RankedEntry.adequacy` and on the price
breakdown. Rejected: NaN (breaks JSON and comparisons).

## 4. Generic weight renormalization
`index = Σ wᵢ·termᵢ / Σ wᵢ` over present terms. With default weights (sum 1) and all
terms present this is exactly P-5. Non-finite or negative weights count as 0.
No term present -> index 0. A zero or non-finite denominator (predicted premium 0,
quoted premium 0) is treated as a null input (`safeDiv`).

## 5. `rank(results)` without weights uses the carried `qualityIndex`
With weights it recomputes every index. Non-knockouts: index desc, then id asc.
Knockouts (`evaluate.knockout`): `distanceToAppetite` asc with null last, then index
desc, then id asc (P-6).
