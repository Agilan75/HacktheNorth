# A08 decisions — Overpass fire-station distance, enrichment runner, unavailable cards

| # | Decision | Reason | Rejected |
|---|---|---|---|
| A08-1 | Fire stations = OSM `nwr["amenity"="fire_station"]` within **8 047 m (5 mi)** via Overpass `out center tags`; nodes use `lat/lon`, ways/relations `center`. Distance = haversine (R = 6371.0088 km), straight line, rounded to 0.01 km with `math.roundTo`. Nearest wins; ties by OSM id. | ISO PPC treats > 5 road miles from a station as unprotected (class 10), so the radius matches the underwriting threshold and bounds the payload (measured live 2026-09-19: downtown Philadelphia → 53 stations, nearest `way/333012807` 0.84 km, 1.9 s). | Road-network distance (needs a routing API); unbounded nearest search. |
| A08-2 | No station within 5 mi → card field "None within 5 mi (straight line)", **no value written**. | Writing 8.05 as a distance would be fabricated; a lower bound is not a measurement. | Writing the radius as a sentinel. |
| A08-3 | Endpoints `overpass-api.de` then `overpass.kumi.systems`, 3 s each (the 6 s budget split, same as A07-2). Server-side `[timeout:3]`. A `remark` containing "error" at HTTP 200 is a failure and falls through to the mirror. Locations are looked up sequentially (public Overpass allows ~2 slots per client). | Overpass instances are frequently overloaded (429/504); a query timeout arrives as HTTP 200 + remark. | One endpoint only. |
| A08-4 | Writes only `locations.<externalId>.fireStationDistanceKm` (declared `locations[].fireStationDistanceKm`), provenance `{ source: 'enrichment', sourceDetail: 'overpass_fire_station: OSM amenity=fire_station, straight-line distance (<endpoint id>)', observedAt: nowIso }`. Module-level cache of the parsed result keyed by coords at 5 dp, 24 h TTL on the injected clock; failures never cached. Card availability rules identical to A07-4 (partial success stays available). | Mirrors the flood plugin so both cards behave the same. | — |
| A08-5 | `defaultPlugins()` = `[flood, fireStation]`, fresh instances each call (caches are module-level, A07-7). `runEnrichment` runs plugins **concurrently**, returns outcomes in plugin order, and **never rejects**. | The routes persist one row per source; one bad source must not sink the other. | Sequential run. |
| A08-6 | Runner backstop per plugin = `PLUGIN_DEADLINE_MS` = 2 × `ENRICH_TIMEOUT_MS` = **12 s**; on expiry the plugin's signal is aborted and it becomes "timeout after 12000 ms". Each HTTP call already stops at 6 s; a geocoded location legitimately spends up to 6 s (Nominatim) + 6 s (lookup). | PRD §8's 6 s is enforced per request by `fetchJson`; a 6 s whole-plugin cap would always kill geocoded locations. | 6 s whole-plugin cap. |
| A08-7 | "Unavailable" outcome (thrown error, timeout, caller abort, malformed outcome, plugin-reported unavailable): `values: []`, card `{ available: false, unavailableReason, fetchedAt: null, fields: [] }` with the plugin's title/attribution; `raw` = the plugin's raw when it returned one, else `{ error }`. | PRD §8 "unavailable card on failure". | Propagating the error. |
| A08-8 | The runner sanitizes available outcomes: source re-keyed to the plugin's, values on undeclared paths dropped, provenance forced to `enrichment` (observedAt defaulted to nowIso). A plugin whose `writes` is empty is cut without running ("Plugin writes no canonical field and is cut"). | PRD §8: enriched values carry `enrichment` provenance; a plugin that cannot move anything is cut. | Trusting plugin output. |
| A08-9 | Note for the checkpoint: `fireStationDistanceKm` is merged/normalized by the engine but no rule, rating factor or contradiction reads it yet (only `tivWeightedProtectionClass`). Under PRD §8's cut rule it moves nothing until a rule consumes it. Not A08's files to change. | Flag, not fix. | — |
