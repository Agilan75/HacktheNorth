# A05 decisions — schema-assist + second-opinion

1. **schema-assist does not apply the 0.8 gate.** It returns every sanitized mapping with its
   confidence; the planner (PRD §7.5 step 3) accepts ≥ 0.8. Reason: a sub-threshold best guess stays
   visible in the trace. Rejected: filtering in the call, which hides the guess.
2. **schema-assist sanitizes in code:** drops mappings for keys it was not asked about and canonical
   paths not offered (also enforced as a response-schema `enum`), clamps confidence to [0,1], keeps
   one mapping per raw key (highest confidence), returns in input key order.
3. **schema-assist degrades to `{ mappings: [] }`** on any failure except `LlmUnavailableError`,
   which is rethrown for the caller to report (same convention as A04 verify-fix). Empty input
   short-circuits without a call.
4. **second-opinion never degrades.** A verdict has no safe default, so every failure (including
   an unconfigured provider and a `degraded` result) throws; layer C records the case as unanswered.
5. **second-opinion `decidingFactor` is constrained** to the 8 `APPETITE_FACTORS` plus `"none"`
   (the engine's `decidingFactorId: null`), enforced by response-schema enum and zod (with
   case/space normalization). Reason: INTERPRETATIONS §7 compares deciding factor exactly. The
   V-8 tie-break rule is *not* given to the model — it is described only as "the knockout factor,
   or else the weakest factor", so it stays an independent reader of the guideline.
6. Facts are rendered sorted by key, `null`/non-finite as `unknown`, so identical cases give
   identical prompts (cacheable by V09). `temperature: 0` on both calls.
7. Offline tests live in `second-opinion.live.test.ts` (only owned test path); see requests/A05.md.
