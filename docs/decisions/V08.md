# V08 decisions — worker pool, verify CLI, 100K test

1. **Case layout.** Index `i` of seed `s` is a full multi-building submission
   (`rollupGenerated(generateSubmission(s, i))`, seed/index re-pinned to the run's,
   `fromSubmission: true`) when `i >= 12 && i % 10 === 9`; every other index is a V02
   vector case (`generateCase(s, i)`), so indices 0..11 stay B1..B12. Exported as
   `caseAt(seed, index)` from worker.ts. 10% submissions = PRD "a smaller share".
   Rejected: a PRNG coin per index (harder to eyeball, same effect).
2. **Chunk seed = run seed.** Every case is a pure function of `(seed, index)` (V02-3), so
   counts are independent of worker count and chunk size — the test asserts 1 vs 3
   workers vs in-process give identical counts and identical first disagreements.
3. **Engine side** is `engineViewForInput` from compare.ts (V05 D1) for both vector and
   submission cases; the same function is installed as the V04 probe
   (`setInvariantProbe(engineViewForInput)`) once per thread. It carries `confidence` but
   **no `predictedPremium`**: there is no fitted commercial rating table yet and the case
   submission has no buildings, so any premium would be meaningless. Consequence:
   `premiumMonotonicInEveryFactor` reports nothing until a probe with a real premium is
   installed. Rejected: pricing against the placeholder table (flat, proves nothing).
   Also not done: differential of the engine's own `rollup` stage against V03's
   `rollupGenerated` — no comparator contract exists for it.
4. **Engine throw = `noCrash` invariant violation**; a throwing invariant, naive, or
   generator = an `errors` entry. Every attempted case counts as completed.
5. **Partial counts.** A `SharedArrayBuffer` stop flag in `workerData`; `runChunk` checks it
   before each case and returns early with `completed < count`, so an interrupted run's
   count covers exactly the cases whose results were recorded. Triggered by
   `maxDisagreements` or the new additive export `requestStop()` (CLI wires SIGINT/SIGTERM).
   A worker that crashes mid-chunk contributes 0 cases plus one error naming how far it
   got; a replacement worker is spawned while work remains.
6. **Kept examples.** First 100 violations / disagreements in (chunkId, position) order,
   deterministic regardless of finish order. Counts are always exact.
7. **CLI.** Flags `--total --seed --workers --chunk --max-disagreements --out`; defaults
   10,000,000 / 20260919 / min(6, cores−1) / 10,000 / 0 / `packages/verify/out`. Writes
   `run.json` (raw RunSummary), `summary.json` (V07 `renderSummaryJson`, preserving any
   layer-C/extraction keys V09 already wrote) and `layers-ab.md`. It does not write
   VERIFICATION.md (BUILD_PLAN CP2: written from the outputs afterwards). Exit 0 only for a
   complete, clean run; 1 otherwise; 2 bad flags; 130 interrupted.
8. **The 100K test is a real gate**: it asserts zero violations and zero disagreements, and
   it currently FAILS on defects in other units (seed 20260919, 100K cases, ~17 s on 4
   workers): 20,662 violations, 1,369 disagreements, 0 errors.
   - `primaryState: ''` / whitespace — engine treats it as missing; G-7 says a present
     non-code value is out-of-list (tier 0, knockout). **Engine bug** (vectorize/state tier).
   - `submissionType: 'NEW_BUSINESS'`, `' new_business '` — naive scores 1; INTERPRETATIONS
     §3.7 "any other value → 0". **Naive (V01) bug.**
   - `peerDistanceIsSymmetric` — distance is `Infinity` for extreme raw values (1e18,
     MAX_VALUE) and 19 cases report 0 distance with differing components. Engine
     peers/scaling overflow, or V05's check needs the out-of-domain skip it already applies
     to scaling (V05 D7).
