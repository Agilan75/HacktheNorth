# C14 decisions — AggregatePage + SVG charts

1. **Consume `AggregateResponse` (client view) as-is.** The page reads `client.getAggregate()` through `useApi`. That view drops `counts.total/byLine/scored/knockedOut`, the knockout factor `label`, `bookAdequacy.underpricedCount/n`, and each one-flip entry's `moveLabel/scoreAfter` when the row is found in the queue. Totals are derived by summing `countsByVerdict` and the histogram; knockout labels are `titleCase(factorId)`; the flip column shows the queue row's `explanationLine`. Rejected: calling the transport directly (not exposed, client.ts not owned). Contract request filed: `docs/contracts/requests/C14.md`.
2. **Adequacy scale domain 0–2 (0%–200%)**, the same clamp INTERPRETATIONS P-5 applies to adequacy. Values outside are pinned to the edge and labelled "(off scale)".
3. **Charts are hand-written SVG in `components/charts/`** (BarList, Histogram, AdequacyScale). Every mark prints its number as text, verdict bars carry `VERDICT_MARKS` glyphs and the REFER bar is outlined (PRD 13: colour never alone), and each chart repeats its data in an `rf-sr-only` table.
4. **Styling is inline with `--rf-*` tokens** because `styles/base.css` is not owned by C14.
5. **Tests live in `components/charts/charts.test.tsx`** (including the page tests), since `pages/AggregatePage.test.tsx` is not in C14's owns list.
6. The page wrapper is a `<section>`, not `<main>`: Layout already renders `<main>`.
