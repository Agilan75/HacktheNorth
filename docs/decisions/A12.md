# A12 decisions — routes: ingest + submissions

| # | Decision | Reason | Rejected |
|---|---|---|---|
| A12-1 | Bad request body or query → 422, `error.code = "INVALID_REQUEST"`, zod issues flattened to `{ path: "a.0.b", message }`. A body that is not JSON is also a 422 with one issue at path `""`. An empty POST body to `/ingest/federato` means `{}` (the whole book). | dto.schemas.ts header fixes 422 + flattened issues; no code name was fixed. Empty body = `curl -X POST` convenience. | 400 for bad JSON; rejecting an empty body. |
| A12-2 | The queue lists **scored rows only** (`result != null`). Order is the repo's queue order (rank asc, unranked last, externalId). `rank` = stored rank, or the row's 1-based position in the scored list when unranked. Filtering and paging happen in memory after that; `page.total` is the filtered count. Default limit `DEFAULT_PAGE_LIMIT` (200). | `QueueRowDto` requires a verdict and score; the book is 158 rows, so in-memory filtering is cheap and keeps filters the repo cannot express (verdict, state, underwriter). | SQL-side paging (cannot filter on JSON result fields). |
| A12-3 | `outOfAppetiteLine` = `evaluate.knockoutFactors` includes `line_of_business`. For those rows `lineOfBusiness` shows Federato's own line (`health`, `cgl`, ...) from the raw bundle's `line_of_business` (Submission record first); otherwise the stored Retrofit line. `?line=` matches the shown value; an in-line row also matches Federato's spelling (`property`). | PRD §11: non-property rows collapse under "Out of appetite: line of business"; the underwriter needs to see which line. | A separate flag column (schema is frozen). |
| A12-4 | `oneFlipFromFit` = verdict ≠ FIT, `flip.flip` has exactly one move, and `flip.verdictAfter === 'FIT'`. | Literal reading of the "1 flip from FIT" badge. | `distanceToAppetite === 1` alone (does not say the flip lands on FIT). |
| A12-5 | `assignedUnderwriter` / detail `routing` = newest `route` action's `payload.routing` (falling back to any action carrying `routing`). `pendingAction` = newest action with status `draft`, `approved` or `sent`. | Routing is recorded as an action (PRD §7.6); those three statuses still wait on the underwriter or broker. | Re-running `route()` on read (business logic in a handler). |
| A12-6 | Detail explanation = `explain()` (F12 template) polished by `narrateCall` then re-checked by `narrateGuard`; any failure keeps the template (`narrated: false`). Result cached in memory per `id@updatedAt`, so Gemini runs once per submission version, not per page view. | PRD §7.7 "When a submission is opened, narrate may polish the wording only". | Narrating on every GET; never narrating. |
| A12-7 | `GET /submissions/:id` accepts the internal id or the external submission number; unknown → 404 `NOT_FOUND`, unscored → 409 `NOT_SCORED` (same as A11's share route). | `SubmissionDetailDto.result` is non-null. | 200 with a null result. |
| A12-8 | Enrichment cards are read from `payload.card` (or the payload itself if it is card-shaped); otherwise a card is synthesized from the row (`available`, `unavailableReason` from `payload.unavailableReason`/`payload.error`). Attached sweep = newest sweep row for the submission via `getSweep()`; while that service is a stub, a private row → `SweepDto` mapping is used (`needsConfirmation` = confidence < 0.6). | schema.ts says the payload holds "the plugin's raw response plus the card it produced"; a failed plugin must still show a card (PRD §8). | Dropping rows without a card. |
| A12-9 | Building rows take the best value per slot (`bestValue`), state/city from the building's location, protection class from the building else the location; `pre1990 = yearBuilt < 1990`, `post2010 = yearBuilt >= 2010`; construction acceptability read from `rollup.pctTivByConstruction` (case-insensitive type match), false when absent. | Same boundaries as the rollup; no re-derivation of the acceptable-construction list in the API. | Re-classifying construction in the route. |
