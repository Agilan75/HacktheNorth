# E03 — rollup decisions

Unit E03 owns `packages/engine/src/stages/rollup.ts` (stage 3). Every boundary
already pinned in `INTERPRETATIONS.md` (3.4, 3.5, 3.6, I-1..I-4, R-AGE-REFER)
was applied as written and is not re-decided here. These are the points the
contracts left genuinely open.

## D1 — `Steel Frame` is the listed `steel` class
G-8 normalizes construction types to lower snake_case, so the live value
`"Steel Frame"` (LIVE_DATA_FACTS: n = 9, appetite **acceptable**) becomes
`steel_frame`, which is not a member of `ACCEPTABLE_CONSTRUCTION` (`steel`).
Taking the normalization literally would score 9 of 129 real buildings as
"other" and contradict LIVE_DATA_FACTS' own appetite column.

**Decision:** a private alias table in `rollup.ts` maps
`steel_frame → steel` (plus `jm → joisted_masonry`,
`noncombustible → non_combustible`, `masonry_noncombustible →
masonry_non_combustible`, which cost nothing and cover spelling drift).
Rejected: widening `ACCEPTABLE_CONSTRUCTION` (frozen, W0-2) and reporting
`steel_frame` as not acceptable (wrong against the measured data).
`ConstructionShare.constructionType` still reports the **canonical** class, so
`Steel Frame` appears as `steel`.

## D2 — `stateShares[].share` denominator
`StateShare.share` is documented as "0..1 of total TIV". Buildings with an
unknown state are excluded from the primary-state computation entirely (I-1),
so dividing by `totalTiv` would produce shares that do not sum to 1 whenever a
building has no location.

**Decision:** the denominator is the TIV of buildings with **both** a known
state and a known TIV, so `stateShares` always sums to 1. `totalTiv` remains
the sum over all known-TIV buildings. Ordering is TIV descending, then the
alphabetically first two-letter code (I-1's tie-break).

## D3 — building → state attribution when `locationExternalId` is absent
A building without `locationExternalId` has no location and therefore no state.

**Decision:** when the submission has **exactly one** location, a building with
no `locationExternalId` is attributed to it; with zero or 2+ locations its
state is unknown. Single-location accounts are the common commercial-property
shape and the attribution is unambiguous there.

## D4 — `pctTivSprinklered`
Not specified in INTERPRETATIONS. **Decision:** mirror the construction factor.
The denominator is every known-TIV building, an unknown `sprinklered` counts as
**not** sprinklered, and the whole field is `null` (component 9 missing) only
when no known-TIV building states sprinklers at all. Rejected: restricting the
denominator to buildings with a known flag, which would let one sprinklered
building out of fifty report 1.0.

## D5 — `tivWeightedProtectionClass` source and degenerate weights
**Decision:** the building's own `protectionClass` wins; otherwise the
building's location's `protectionClass` (LIVE_DATA_FACTS: `Location.protection_class`
is integer 1–10 and always present, while buildings often omit it). The mean is
TIV-weighted over known-TIV buildings with a known class; when every such
building's TIV is exactly 0 the weights degenerate and an unweighted mean is
used instead of returning null.

## D6 — `fiveYearLoss` is not floored, and "claims never fetched"
I-4 floors the loss at 0 "before the 3.3 comparison". **Decision:** the floor
belongs to the evaluate stage, not to the rollup; `rollup.fiveYearLoss` is the
raw signed sum so negative recoveries stay visible on the buildings/claims
panel. Consumers of the loss-value factor must apply `max(0, x)` themselves.

I-4 makes the loss `null` when claims were never fetched. That is only
observable through the raw bundle. **Decision:** `fiveYearLoss = null` iff
`history` is empty **and** `submission.raw` is present **and** `raw.records`
has no `Claim` key (or the loss window itself is unknown). A canonical
submission with no raw bundle and no claims yields a **known 0**, so engine
fixtures built without a `RawBundle` are not silently marked incomplete.

## D7 — local `bestValue` fallback (contract-adjacent)
`Sourced<T>` slots are resolved with `bestValue` from
`packages/engine/src/util/fields.ts` (E01). E01 runs in parallel and its body
may still throw `NOT_IMPLEMENTED:E01` when rollup's own tests run.

**Decision:** `rollup.ts` calls `bestValue` first and falls back to a private
implementation of the ordering documented on `bestValue` (highest confidence,
then enrichment > answer > sweep > self_reported, then latest `observedAt`,
then insertion order) **only** when the thrown error message starts with
`NOT_IMPLEMENTED`. Any other error propagates. Marked `TODO(contract)`; the
fallback should be deleted once E01 has landed. No new shared helper was
created and `util/fields.ts` was not touched.
