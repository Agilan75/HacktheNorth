# E13 — decisions (rules/commercial.json)

## D-1 — rules match vector component keys, not raw strings
Every appetite rule conditions on a `vectors/commercial.json` key
(`isNewBusiness`, `stateTier`, `totalTiv`, …) or on `rollup.oldestYearBuilt`.
That is what `evaluate`, `flipBounds` and `fixHintFor` read, and it avoids the
casing trap entirely: Federato `business_type` `new`/`renewal` and the eight
`construction_type` values are mapped upstream (adapter → canonical → rollup,
incl. rollup's `steel_frame → steel` alias). The data values are named verbatim
in each rule's `interpretation` so the rule card shows the real enum.
Rejected: `submissionType eq "New business"` style string rules — they match zero records.

## D-2 — disjoint rules per factor (G-9)
Acceptable bands around a Target band are split (`AG-TIV-A-LOW`/`-HIGH`,
`AG-PREM-A-LOW`/`-HIGH`, `AG-AGE-A` requires `pctTivPost2010 <= 0.5`), so exactly
one scoring rule fires for any known input. The test sweeps every boundary.
Rejected: overlapping Acceptable rules resolved by precedence (E06 D-2 handles
it, but disjoint data removes the ambiguity for V01 and the flip intervals).

## D-3 — citation format
`{ doc: "APPETITE_GUIDELINES.pdf", section: "p2 \"<Factor row>\"", quote: <exact cell> }`,
matching INTERPRETATIONS' `AG p2 "<Factor>"`. The quote is always the cell from
the column matching the rule's tier; the refer rule quotes the "Older than 1990"
cell and carries R-AGE-REFER in `interpretation`. Wrapped PDF lines are joined
("non-\ncombustible" → "non-combustible").

## D-4 — interpretations block carries only PRD 6.6's four (I-1..I-4)
T-BLANK is already applied by the engine constants; listing it would surface on
nearly every account.
