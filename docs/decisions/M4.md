# M4 — ScanOverlay (the sweep's coverage overlay); the 3D dome is cut

File: `apps/mobile/src/ui/ScanOverlay.tsx`. Import it as `import { ScanOverlay } from '@/ui/ScanOverlay'` (the `@/ui` barrel belongs to M3 and does not re-export it).

Usage (M6, `/sweep`): render the camera, then `<ScanOverlay state={captureState} onFinish={...} onUsePhotos={...} finishing={submitting} style={StyleSheet.absoluteFill} />`. The root uses `pointerEvents="box-none"`, so only the buttons take touches.

## The 3D dome was cut (for the README)

PRD §11 planned a 3D coverage dome (`expo-gl` + `three` + `@react-three/fiber/native`) with a 45-minute time box and the 2D Skia ring as the fallback. We shipped the fallback on purpose (DECISIONS R3-2, rung (c) of the cut ladder):

- The 3D stack (`expo-gl`, `three`, `@react-three/fiber`) was never installed, and this build does not install packages.
- The app must run in Expo Go on a real iPhone. No build agent can drive an iPhone, so nobody could confirm a 3D render works there. Shipping a dome nobody has seen render is worse than shipping a ring that works.
- `/confirm` needs the 2D ring anyway (PRD §11 radar ring), so the ring costs nothing extra.
- The ring shows the same thing the dome would have shown: 36 panels of 10° that fill as you turn. The one thing lost is pitch (looking up or down), which the dome would have drawn and the ring does not.

`ScanDome.tsx`, which OWNERSHIP.json lists for M4, was not created. Nothing imports it.

Honest README line: *"The coverage overlay is a 2D ring (Skia). We planned a 3D dome, but cut it because we could not verify a 3D render inside Expo Go in the time we had. The ring shows the same 36 ten-degree segments."*

## Decisions

1. **M4-1 The hint points at the LARGEST uncovered arc (M2's `summarize(state).turn`), not the nearest gap (M3's ring sentence).** This follows the brief. So the overlay renders `ScanRing` with `showText={false}` and hides it from the screen reader. The overlay provides its own single `progressbar` element (percent, hint, photo count), so VoiceOver never hears two different directions. Rejected: showing both hints.
2. **M4-2 Finish is locked until M2's `canFinish` is true** (at least 27 of 36 panels AND at least 1 frame, which the API needs). The percent shown is M2's floored `coveragePctDisplay`, so the display never reads 75% while Finish is still locked.
3. **M4-3 A locked Finish is still tappable and explains itself.** A disabled `Pressable` ignores taps without any feedback. The locked control uses `accessibilityState.disabled` (VoiceOver reads "dimmed"), a `accessibilityHint` with the reason, visible reason text under it, the word "locked" in its label, and a dashed outline (a shape, not only a colour). Tapping it speaks the reason and gives a warning haptic. When it unlocks, it becomes the normal kit primary `Button`.
4. **M4-4 Direction is an arrow glyph (→ / ←) plus the words "Turn left/right about N degrees"**, with N rounded to 10 so compass noise does not make the text flicker.
5. **M4-5 Announcements are rationed.** The overlay speaks at each 25% step, when Finish unlocks (with a success haptic), when the 15-photo cap is reached, and when the turn direction flips, but no more than once every 4 s. It never speaks on each compass tick. Set `announce={false}` to switch it off.
6. **M4-6 The upload path is an equal choice.** When the screen passes `onUsePhotos`, a full-width "Use photos instead" button sits right under Finish. It is always visible and never hidden behind an error.
7. **M4-7 Legibility over the camera.** All text sits on a dark translucent scrim (`rgba(31,30,27,0.78)`, the Ink colour) in Paper. The ring uses its `onCamera` variant. At text scale 1.6x and above, the ring shrinks to 70% so the words keep their room. Text is never capped below the kit's own caps.
8. **M4-8 No tests file.** M4 owns one `.tsx` file that imports react-native, so it cannot run in the node vitest project. All the logic it shows comes from M2's `capture.ts` and M3's `ringModel.ts`, which are already tested. Checked with `npx tsc -p apps/mobile --noEmit`: clean for this file. The only error is the known one in `packages/engine/src/data.ts(54)`, which belongs to another unit.

## Human checklist (iPhone, Expo Go, after M6 mounts the overlay on /sweep)

Nothing here has been run on a device.

1. **Renders over the camera:** the ring sits at the top with the % in the middle, "Photos: N of 15" under it, and the hint panel plus Finish at the bottom. All text is readable against a bright window and against a dark wall. Pass: you can read every word at arm's length.
2. **Largest-gap hint:** turn about 180° right from the start, then face back toward the start. Pass: the arrow and words point to the big unscanned half, not to a small hole next to you. Turning the way it says reaches unfilled tiles in about the stated degrees. Right = clockwise when seen from above.
3. **Finish lock:** below 75%, Finish shows a dashed outline and reads "Finish (locked until 75%)", with the reason under it. Tap it. Pass: nothing navigates, you feel a buzz, and (with VoiceOver) you hear the reason. Keep turning until the % reads 75. Pass: you feel a success buzz, Finish turns into a solid red "Finish scanning" button, and tapping it moves on.
4. **Upload choice:** "Use photos instead" is visible from the first second, is at least a fingertip tall, and opens the photo picker.
5. **VoiceOver:** swipe through the screen. Pass: there are three stops — "Room scan coverage, N percent…" with the hint and photo count, then Finish (with "dimmed" and the reason while locked), then "Use photos instead". It announces 25/50/75/100%, "You can finish now" and the 15-photo cap, and it is silent while you turn steadily in one direction.
6. **Largest text (AX5):** the ring shrinks, the words wrap instead of being cut off, both buttons grow taller, and nothing overlaps the ring. If the bottom panel runs off the screen at AX5, M6 should wrap the overlay in a ScrollView.
7. **Grayscale** (Settings > Accessibility > Display > Color Filters): the direction, the locked state and scanned vs unscanned tiles can all still be told apart.
8. **Touches pass through:** tapping the empty camera area between the ring and the bottom panel does nothing wrong. The overlay does not block whatever M6 puts under it.
