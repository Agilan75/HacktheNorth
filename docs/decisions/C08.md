# C08 decisions — Pricing + PeerBenchmark panels

1. **Underpriced threshold is a private copy of `ADEQUACY_UNDERPRICED = 0.9`** (engine `constants.ts`, PRD 6.7). `@retrofit/engine` is not a console dependency. Strict `< 0.9` → "Underpriced for the risk"; otherwise "Adequate for the risk"; `null` → no badge. Only picks a label; never alters a number. Rejected: adding engine as a console dep (frozen package.json).
2. **No per-factor dollar amounts.** `PricingFactorView` carries multipliers only; converting to dollars would be client-side arithmetic (PRD 10/13 forbid). Each factor shows `×m.mm`, a text direction (Raises / Lowers / No effect) so colour never carries meaning, and its basis.
3. **Adequacy** shown as a percent (`0.84` → `84%`) plus the raw ratio "(0.84 quoted ÷ predicted)".
4. **Coarse match** = `0 < comparedComponentCount <= 3` (the reduced vector of PRD 6.4 is three components; a full vector compares nine). `PeerRowView` has no per-row coarse flag, so the label is benchmark-level. Rejected: `< 9` (a full vector with one missing component is not coarse).
5. **Peer order is the engine's** (distance asc, id tiebreak, P-4); median/mean are rendered from props (P-3), never recomputed. Distance at 3 dp via `formatScore` (unitless; `formatDistance` is km).
6. **Peer names link** to `submissionPath(id)` from the frozen `App.tsx`, so the panel needs router context (tests wrap in `MemoryRouter`).
7. A standing footnote states peers are a rate/loss benchmark only — every full-vector account was bound (PRD 6.4).
