# C12 — ActionsPage decisions

1. **Three blocks.** Simulated-sending notice (PRD §14 risk row) → Outbox (drafted broker requests with Approve) → "Rank movement from replies" list → full action log with stage filter. Rejected: one table only; the approve affordance gets lost among routes.
2. **Outbox = `type === 'request' && status === 'draft'`.** PRD §7.6: the underwriter approves the drafted request. A draft of any other type shows in the log but has no Approve button.
3. **Stages.** Awaiting approval = `draft`; Sent = `approved | sent`; Replied = `replied`, or a non-failed `reply` action; Failed = `failed`. Applied routes/rescores/logs appear under All only, so Replied never counts something no broker answered.
4. **Rank movement** = `beforeRank − afterRank` (rank 1 is best, so #7 → #3 is "up 4 places"). Display arithmetic on API-supplied ranks only; the page never computes a rank or score.
5. **Order** newest first by ISO `createdAt`, action id tiebreak.
6. **Mutations** go through `useApiClient()` (`approveAction`, `planActions`), then `reload()` the log; failures render in a `role="alert"` and do not reload. A "Run action plan" button is included because the log is empty until `POST /actions/plan` runs.
7. **Test file** `apps/console/src/pages/ActionsPage.test.tsx` is not in C12's `owns` list, but the task requires a colocated test and no unit owns that path. Same precedent as C04's QueuePage.test.tsx.
