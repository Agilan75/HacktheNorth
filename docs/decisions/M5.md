# M5 — `/` (Your rooms) and `/new` (New sweep)

Files: `apps/mobile/app/index.tsx`, `apps/mobile/app/new.tsx`. `_layout.tsx` left unchanged (see M5-6).

## Decisions

| # | Decision | Why | Rejected |
|---|---|---|---|
| M5-1 | **The rooms list is in memory, for this app launch.** A module-scope registry in `index.tsx` subscribes to `sessionStore` and records a room each time the session gets a new `sweepId`. Each card then does `GET /sweeps/:id` and shows a `SkeletonCard` until it answers. | The API has no "list sweeps" route (contracts `ROUTES` is frozen) and no persistent storage package is installed. The screen says "Rooms are kept until you close the app." | Adding a list route or AsyncStorage (both out of bounds). |
| M5-2 | **Cards show only what the API returned**: stage in plain words, term, and the verdict as a `VerdictPill` with tenant wording ("We can quote this room" / "A person needs to check this" / "We cannot quote this as it is"). No price on the card. | PRD invariant: the app renders numbers, never makes them; the price and its breakdown belong on /verdict (M8). | Showing the premium on the card. |
| M5-3 | **/new shows the two ways in as two equal cards**, same size, same primary button style, one after the other: "Scan the room with the camera" and "Upload 3 photos instead", under "Both ways give you the same quote." | PRD 11 inclusivity: upload is a first-class path, not an error fallback. | Upload as a small link under the scan button. |
| M5-4 | **The upload path is completed on /new**: pick up to 3 photos (ordered multi-select, PHPicker so no library permission prompt on iOS 14+), downscale to 768px long edge JPEG q0.7 with `manipulateAsync` (also turns HEIC into JPEG), bearings from `uploadBearings(n)` (3 -> 0/120/240), `setFrames(frames,'upload')`, `buildCreateRequest`, send through the shared offline queue, `setSweepId`, then `router.push('/analyzing')`. Queued -> a notice, and it moves on by itself once `waitFor` resolves. | Does not depend on /sweep (M6) knowing about an upload mode, so the inclusive path works even if the camera screen does not. 768/0.7 matches the prototype encoder. | Routing to `/sweep?mode=upload` (an unwritten contract with M6). |
| M5-5 | **Fewer than 3 photos is accepted**, spaced evenly (1 -> 0°, 2 -> 0/180). | The API decides whether the coverage is enough and asks for more; the app should not block a person who only has two photos. | Forcing exactly 3. |
| M5-6 | **`_layout.tsx` not edited.** | Its header says FROZEN (W0-4) and OWNERSHIP.json gives it to W0-4, though the M5 task listed it. It already registers every route with plain titles. The foreground retry of the offline queue (`AppState` -> `retryNow()`) lives in `index.tsx` instead, which stays mounted at the bottom of the stack. | Editing a frozen file. |
| M5-7 | **Opening a room card**: resets the session, restores label/term/`sweepId`, then goes to `/verdict` when stage is `done`, else `/analyzing` (which polls and routes to /confirm or /questions). | /analyzing owns the stage -> screen routing; duplicating it here would drift. | Routing every stage from the list. |
| M5-8 | **"New sweep" resets the session** before opening /new; the scan path clears frames and `sweepId` before `/sweep`. | A new room must not inherit the last room's photos or id. | Keeping the previous label as a default. |
| M5-9 | Submission id is free text, trimmed, blank = not attached (`attachSubmission`). Not validated on the phone. | The API validates it; the phone has no way to list submissions. | Format validation. |

## Assumptions about sibling units

- M6 `/sweep` reads `roomLabel`/`termMonths`/`submissionId` from `sessionStore`, captures, sends, and sets `sweepId`.
- M6 `/analyzing` reads `sweepId` from `sessionStore` and does not POST again when it is already set.

## Human checklist (iPhone, Expo Go)

Nothing here has been run on a device.

1. **First launch.** `/` shows "Your rooms", a "No rooms yet" card, and a red "New sweep" button pinned above the home indicator. Pass: no red error screen.
2. **Name required.** On /new, leave the room name empty and tap either path. Pass: "Problem: Give the room a name…" appears under the field and VoiceOver reads it; nothing opens.
3. **Term.** Tap 4, 8, 12 months. Pass: the selected one is filled dark with a ✓ (check in Grayscale filter too); VoiceOver says "8 months, radio button, selected".
4. **Two equal paths.** Both cards are the same size with the same button style. Pass: at default and at AX5 text size both buttons are fully visible and grow taller rather than clipping.
5. **Upload path.** Tap "Upload 3 photos instead", pick 3 photos (include one HEIC from the iPhone camera). Pass: the button reads "Getting photos ready…" then "Sending photos…", then /analyzing opens and the API log shows `POST /sweeps` with 3 frames at bearings 0/120/240.
6. **Cancel picker.** Open the picker and cancel. Pass: back on /new, button idle, no error.
7. **Offline upload.** Airplane Mode on, upload 3 photos. Pass: "Queued. Your sweep will send when you are back online." Turn Airplane Mode off (or background and foreground the app). Pass: /analyzing opens by itself within about a minute.
8. **Scan path.** Name a room, tap "Scan the room with the camera". Pass: /sweep opens (M6's screen).
9. **Rooms list.** After a sweep or upload, go Back to `/`. Pass: the room appears; it first shows a pulsing grey skeleton card, then the room name, a stage line like "Waiting for your answers · 12-month term", and once done a verdict pill with words and a glyph.
10. **Card opens.** Tap a finished room -> /verdict; an unfinished one -> /analyzing.
11. **API down.** Stop the API, return to `/`. Pass: each card shows "Problem: …" with a "Try again" button (44pt), and Try again reloads it after the API is back.
12. **VoiceOver on /.** Swipe through: "Your rooms, heading", the room card read as one button with name, stage, result, term and source, then "New sweep, button".
