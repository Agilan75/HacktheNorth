# A15 — sweeps routes: decisions

1. **Who drives `stage`.** The route does. `POST /sweeps` calls `createSweep`, answers
   **201** with the sweep as created, then drives it in the background with
   `advanceSweep` one stage at a time until a resting stage (`questions`, `done`,
   `failed`). `GET /sweeps/:id` re-kicks the driver for a sweep found mid-pipeline
   (e.g. after a restart). Rejected: advancing one stage per poll (a slow Gemini
   stage would block the poll and make the phone's loader lie about progress).
   **Contract for A18:** `createSweep` should persist and return without running the
   pipeline itself; `advanceSweep` runs exactly one stage and returns the new
   `SweepDto`. If A18 instead runs the whole pipeline inside `createSweep`, the
   driver sees a resting stage and does nothing — still correct.
2. **One driver per sweep per process** (an in-memory set), so concurrent polls never
   double-advance. A drive stops when the stage does not move, and is capped at 12
   advances, so a non-advancing service can never spin. Advance errors go to
   `captureError`; marking the sweep `failed` is A18's job.
3. **Status codes.** Malformed JSON → 400 `BAD_REQUEST`; schema failure → 422
   `VALIDATION` with flattened zod `issues` (the `ErrorDto` doc says 422 carries
   issues); unknown sweep → 404 `NOT_FOUND` (checked with `getSweep` before
   `submitAnswers` / `nextQuestion` / `verifyFix`); everything else 200.
   Service `NOT_IMPLEMENTED` errors surface as 501 via `app.onError`.
