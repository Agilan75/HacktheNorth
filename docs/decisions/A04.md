# A04 decisions — verify-fix + narrate

1. **Both calls go through `generateJson(provider, req)`** (A02's zod + one retry + degrade wrapper), never `provider.generateJson` directly. Rejected: calling the provider directly, which would skip the retry.
2. **narrate survival check lives inside the per-request zod schema** (`superRefine`). A rewrite that drops, changes, reformats (`$88,000` -> `$88K`) or invents a numeric token, drops the recommendation word (whole-word, case-insensitive; `reviewed` does not count as `review`), exceeds 900 chars or 4 sentences fails validation, costs the one retry, then the call returns the template. Tokens are compared as written text against the template's tokens, not against `input.numbers` values, because the template already fixed the formatting. F12's `narrateGuard` still runs downstream; this is defence in depth, not a replacement. Rejected: importing `narrateGuard` (takes an `Explanation`, not a `NarrateInput`, and would couple the call to F12).
3. **narrate never throws.** Unconfigured provider, provider error, degraded result, or failed survival -> `{ text: input.template }`. Callers detect narration by `text !== template`.
4. **verify-fix degrades conservatively**: any failure or degraded result -> `{ stillPresent: true, confidence: 0, reason: "The photo could not be checked, so the hazard is still counted." }`. A fix is never credited without evidence. `LlmUnavailableError` is rethrown so the route can report the missing key. Confidence is clamped with `math.clamp01`; reason is single-lined and capped at 400 chars. Rejected: throwing on every failure (the route would have to invent the same safe default).
5. **Tests live in `narrate.live.test.ts`** because it is the only test path A04 owns. The offline block uses `createFakeLlm`; the live block is `describe.skipIf` unless RUN_LIVE=1 + key + provider. See `docs/contracts/requests/A04.md`.
