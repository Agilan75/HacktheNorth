# E14 — decisions (rules/tenant.json, rules/extensions.json, questions/tenant.json)

No stub files existed for E14 (W0-5 "Stubs that do not exist at all"); the three
JSON files were created at `packages/engine/{rules,questions}/` per W0-5 blocker 5.

1. **Condition fields are vector component keys** (`hazardPortableHeater`,
   `smokeDetectorCount`, `pctTivSprinklered`, ...), because rules address
   components by key (types.ts `VectorComponentSpec.key`) and `evaluate`/`voi`
   resolve keys first. Rejected: canonical paths — they work in `evaluate` via the
   alias map but not in `vectorResolver` alone.
2. **Tenant weights** (sum exactly 1, `|Σ−1| ≤ 1e-9`): heater-near-combustible
   0.15, blocked exit 0.15, portable heater 0.10, power bar 0.10, smoke 0.10,
   extension cord / candle / stove / window AC / water heater / high-value /
   building age 0.05 each, contents 0.025, term 0.025. Life-safety fire and
   egress hazards weigh most. No source document exists; these are Retrofit's.
3. **Only two tenant knockouts**: heater within 20° of soft furnishings, and a
   blocked exit. Power-bar overload, no smoke detector, pre-1950 building,
   high-value contents and contents over $100K are `refer`. Other hazards are
   `acceptable` and surcharge through the rating table. Absence of a hazard fires
   no rule. Boundaries: `yearBuilt < 1950` refer, `1950 ≤ y < 1990` acceptable,
   `≥ 1990` target; `contentsLimit ≤ 100000` target, `> 100000` refer;
   `smokeDetectorCount == 0` refer, `≥ 1` target.
4. **`ratingFactor` names the rating-table column path** E07's `priceTenant`
   reads: `hazards.<key>`, `smokeDetector.present|absent`, `buildingAge`,
   `contents`. Term has no rule (neutral factor), so no rule carries `term`.
5. **Citations**: tenant rules cite "Retrofit tenant rulebook" with the rule's
   own statement as the quote — there is no Intact document to transcribe.
   Extension quotes begin "Retrofit's own rule:" so they are labelled as ours
   everywhere (PRD 6.6). The two interpretations that quote the PRD quote it
   verbatim.
6. **extensions.json is commercial-only.** The schema forces one line of
   business per rulebook, and room hazards are already the tenant rulebook's.
   Sprinklers partition at 50% of TIV (refer only above $100M TIV, so the
   rule does not REFER most of the book); protection class ≤ 4 target, 4–9
   acceptable, ≥ 9 refer. `weights: {}`; no rule is `not_acceptable`.
7. **Questions** use canonical source paths as `field` (answers are written to
   canonical paths by merge; `voi` indexes both). One per tenant component (14).
   Booleans carry explicit Yes/No options for plain labels; term options are
   exactly `TENANT_TERMS_MONTHS`.

Known gap for another unit: `evaluate` (E06) scores only the eight commercial
`APPETITE_FACTORS`, so tenant weights/knockouts do not yet reach the tenant
appetite score or knockout mask; fired tenant `refer` rules do reach the verdict.
