# F02 decisions — Federato snapshot

1. **Credentials via `apps/api/src/env.ts`, imported by path at run time.** `packages/federato` cannot statically import an app (rootDir, dependency direction), so `scripts/snapshot.ts` does `await import(<repo>/apps/api/src/env.ts)` and calls `loadEnv()` + `federatoEnv()`. Result: no `process.env` read anywhere in `packages/federato`. Rejected: reading `process.env` in the script (allowed by the task, but breaks the "only env.ts reads process.env" grep).
2. **Assert before write.** `buildSnapshot()` pulls everything, checks all 12 counts against `EXPECTED_COUNTS`, checks the deep query returned 27 policies with `insured`/`submission` objects, a hydrated building and a premium, and throws listing every mismatch. Nothing is written on failure, so a short pull never replaces a good snapshot. Rejected: write-then-verify.
3. **Paging by offset += rows received, until `total` reached.** Survives a server-side limit cap; throws if a page adds no new ids (handler ignoring offset). Measured live: every resource fit in one 500-row page except ExposureUnit (938, two pages) and offset was honored.
4. **Hydrated query stored in its own file**, `packages/federato/snapshot/policy-property-hydrated.json` (`{fetchedAt, payload, total, results}`), because `FederatoSnapshot` (frozen) has no slot for it and its `records` must stay unmodified flat rows. Payload is the LIVE_DATA_FACTS query verbatim, exported as `HYDRATED_POLICY_QUERY`.
5. **One record per line serialisation**, stable resource order and records sorted by id: 634 KB snapshot + 106 KB hydrated, and a refresh diff shows per-record changes.
6. **Relative snapshot dirs resolve against the repo root** (located from `import.meta.url`), matching `SNAPSHOT_DIR` being repo-relative; works from both `npm run` in the package and the API at the root.
7. **`buildSnapshot` / `HYDRATED_POLICY_QUERY` / `HYDRATED_POLICY_FILE` added as new exports** of `scripts/snapshot.ts` (additive, not through the frozen barrel) so the pull/assert logic is testable offline with an injected adapter.
8. **No RUN_LIVE gate in the script.** It is an explicit operator command; the vitest guard still blocks any test from reaching it.
