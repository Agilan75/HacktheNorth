# V01 — decisions

## D1. String comparison is trim + case-fold
INTERPRETATIONS G-7 fixes trim + upper-case for state codes; G-8 fixes lower
snake_case for construction. Nothing states the handling of `submissionType`
and `lineOfBusiness`, so V01 trims and lower-cases them before comparing to
`new_business` / `commercial_property`. Rejected: exact `===` matching, which
would make `'New_Business'` a knockout and disagree with a case-insensitive
engine on hostile generated cases.

## D2. An empty or whitespace-only string is KNOWN, not missing
G-7: "Anything else is out-of-list, not missing, unless the field is absent."
`''` is present, so `primaryState: ''` is Not Acceptable (tier 0, knockout),
and likewise `submissionType: ''` and `lineOfBusiness: ''`. Only `null` (and
a non-string value) is missing. Rejected: treating `''` as missing, which
would raise completeness-driven REFER where the table says the value is
out-of-list. Flagged for the CP1 differential: if the engine's rollup emits
`null` rather than `''` for an unknown state this never fires in practice.

## D3. `building_age` is jointly known
NAIVE_SPEC 5.3 and V-6 state components 5 and 6 are always jointly known or
jointly missing. V01 enforces that rather than assuming it: the factor is
known only when BOTH shares are finite, and then contributes 2 to the
completeness numerator. A half-populated pair (possible only from a hostile
generated case) is treated as missing on both components.

## D4. No flooring or clamping of hostile numbers
Negative TIV, negative loss and shares outside `[0, 1]` are compared as given.
I-4's "floored at 0" applies to the rollup that produces `fiveYearLoss`, not
to the tiering, and the two readings agree for every value: a negative loss is
Acceptable either way.

## D2 superseded at CP1 (INTERPRETATIONS G-11, amended G-7)
D2 is **superseded**. The 100K differential showed the contract was silent on
blank `submissionType` / `lineOfBusiness`, and the engine and V01 filled the
gap differently (V01: known + out-of-list → knockout). CP1 added G-11 and
amended G-7: every categorical field is trimmed and case-folded, and a value
that is empty or whitespace-only after trimming is **missing**, like `null` —
0 points, lowers completeness, never knocks out. The oracle's `code()` helper
now returns `null` for blank strings. G-11 also makes `"new"` the same known
value as `"new_business"`, so V01 accepts both (any case, trimmed); `renewal`
and every other non-blank string remain Not Acceptable. Fixed by CP1 fixer
FX3; see `docs/decisions/CP1-FX3.md`.
