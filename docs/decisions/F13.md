# F13 decisions — actions (request, validators, apply-reply, routing)

**D-1 State -> region map.** Federato publishes no mapping. Live `Underwriter.region` values are West, Midwest, South, Southeast (Broker adds Northeast). Retrofit's map: West = AK AZ CA CO HI ID MT NM NV OR UT WA WY; Midwest = IA IL IN KS MI MN MO ND NE OH SD WI; South = AR LA OK TX; Southeast = AL FL GA KY MS NC SC TN VA WV; Northeast = CT DC DE MA MD ME NH NJ NY PA RI VT. Rejected: census regions (no "Southeast" in them, so underwriter #4 could never be reached).

**D-2 Routing tie-break.** Among underwriters that match the region and whose authority covers the limit (inclusive `>=`), assign the one with the *smallest* covering authority, then lowest id — keeps larger authority free. Unknown state, unmapped state, or unknown requested limit => `needsSeniorReferral`. Data note: property requested limits run $1M–$124M against a top authority of $25M, so most property accounts route to senior authority. That is the dataset, not a bug.

**D-3 Request triggers.** `missing_data` only when verdict is REFER; `high_contradiction` on any open HIGH contradiction regardless of verdict; `one_flip_from_fit` when verdict != FIT and a flip with `verdictAfter = FIT` exists (1 or 2 moves — "one flip", not "one move"). A trigger is recorded only if it contributed a field. Fields are deduped by canonical path, in trigger order.

**D-4 Field paths.** Missing rollup components are asked at the most specific writable path: `buildings.<id>.{tiv,yearBuilt,constructionType}`, `locations.<id>.state`. Building/location gaps are asked on a REFER account even when the rollup component is known (PRD example "year built for Building C is missing"). With zero buildings/locations (the 11 no-policy accounts) the path is the wildcard `buildings.*.<leaf>` / `locations.*.<leaf>`; five-year loss is `rollup.fiveYearLoss`. Non-required components (9, 10) are never requested. **Known limit:** engine `merge` (E04) cannot write wildcard or `rollup.*` paths, so answers to those are validated and logged but dropped at merge until the engine can create buildings from a schedule of values.

**D-5 Extraction validation.** Rejection precedence: not_requested > wrong_type/unparseable > out_of_range > quote_not_found > low_confidence. `wrong_type` = JS type cannot carry the kind (e.g. boolean for a year); `unparseable` = right JS type, text that does not parse. Values are coerced (money `$162.5K` -> 162500, year floored per G-5, `60%` -> 0.6, bare ratio must already be in [0,1], state upper-cased 2 letters, submission type -> `new_business`/`renewal`). Range: vector spec component min/max when the path is a component source, else a fixed leaf bound (years 1800–2100; no clock in this module). Quote match is on normalised text (case, whitespace, typographic quotes/dashes). Confidence is clamped to [0,1]; non-finite -> 0. Gate is `MIN_EXTRACTION_CONFIDENCE` (0.8, inclusive). Two clean values for one path that disagree are both withheld as `needsConfirmation` with rejection `low_confidence`.

**D-6 Draft validator.** A field "appears" when its label (minus the "for <entity>" tail) or a leaf synonym appears, AND for entity paths the entity name/id also appears. "Extraneous" = a request sentence (has `?` or a request cue) that names none of the selected fields but names a known field phrase. Heuristic by nature; tuned to avoid flagging why-context sentences.

**D-7 apply-reply.** One `ExternalValue` per accepted path, `source: 'answer'`, `confidence` omitted so V-7's fixed 0.8 applies (the model's number never reaches the engine). `after` is null — the API re-scores. `conflictingPaths` compares accepted values against `self_reported` values only (strings via G-8 snake-case, numbers within 1e-6).
