# V09 decisions — layer-C runner + `verify:llm` CLI

1. **Provider and real cases are set with `configureLayerC`.** The frozen `runLayerC(config)` /
   `judgeOne(caseId, factsText)` carry neither, so layer-c.ts exports additive helpers:
   `configureLayerC({ llm, realCases, onProgress })`, `lastLayerCRun()` (errors, cached count,
   deciding-factor agreement), `REAL_STRATUM`. `judgeOne` only works for a case `runLayerC`
   registered (stratum + engine view come from there). Rejected: reading `.env` inside layer-c.ts.
2. **Agreement = same verdict** (PRD §12: "would a careful reader reach the same verdict?").
   Deciding-factor match is counted separately (`decidingFactorAgreed`, reported in
   VERIFICATION.md run notes). Rejected: requiring both — the V-8 tie order is not a reading question.
3. **Unanswered cases** (second-opinion throws; A05 never degrades) are excluded from total/agreed,
   never cached, listed in `out/layer-c.json` and the CLI output, and retried on the next resumed run.
   CLI exits 1 while any remain. An engine throw during planning is recorded the same way.
4. **Cache:** one JSON file per case id under `cacheDir`, valid only when version, case id,
   sha256(guideline brief + facts text) and provider name all match — a guideline edit or a
   fake-provider entry never stands in for a Gemini answer. Writes are atomic (tmp + rename).
   `resume: false` ignores reads but still rewrites entries.
5. **Concurrency:** N async lanes over one index (default 2 in the CLI); order of results is
   the planned order (real cases first, then `stratifiedSample` order) regardless of completion order.
6. **Real submissions come from a file**, `packages/verify/out/real-inputs.json`
   (`[{ caseId, input: NaiveInput }]`, zod-checked). The snapshot is not yet captured and turning
   snapshot records into rolled-up facts needs the engine + federato pipeline, which layer-c.ts may
   not import (types.ts header). Missing file → 0 real cases with a loud warning; a count ≠ 38 warns.
   Whoever runs CP2 (or I1) must write that file from the engine rollup of the 38 property submissions.
7. **Layers A+B input:** `out/run-summary.json` (a `RunSummary`, expected from V08's `npm run verify`).
   Missing → a zero placeholder so VERIFICATION.md still renders, with a warning.
8. **Extraction check runs by default** (`--no-extraction` skips it) because CP2 runs it with
   verify:llm and `renderSummaryJson` leaves `extractionFieldAccuracy` for V09 to fill.
   Outputs: `out/extraction.json`, an "Extraction check" section appended to VERIFICATION.md.
9. **Defaults:** 2000 generated, seed 1, concurrency 2, out `packages/verify/out`, report
   `VERIFICATION.md` at the repo root; relative paths resolve from the repo root.
10. **Facts go to second-opinion as one record entry per `- Label: value` line** of `factsForCase`
    text, so the prompt keeps one fact per line (A05 sorts keys, deterministic).
11. The colocated test `packages/verify/src/layer-c.test.ts` is not in V09's `owns` list; written
    under the "write the colocated test" instruction, same as V07's tests.
