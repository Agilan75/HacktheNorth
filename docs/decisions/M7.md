# M7 decisions — `/confirm` and `/questions`

Files: `apps/mobile/app/confirm.tsx`, `apps/mobile/app/questions.tsx`. Built on M1 (`@/lib/api`, `@/lib/session`) and M3 (`@/ui` kit + `ScanRing`).

## Decisions

1. **M7-1 The API decides what is uncertain.** `/confirm` renders `SweepDto.needsConfirmation` as sent (the API applies the 0.6 cut, PRD 9.3 step 7). The screen never re-filters by confidence, never shows or computes a score, verdict or price. Rejected: filtering `observations` by `confidence < 0.6` on the phone (a second copy of an engine threshold).
2. **M7-2 Sweep id = `?id=` route param, else `session.sweepId`.** Other stubs push `/confirm` with no params today; both work. `/confirm` → `/questions` → `/verdict` pass `params: { id }` so a deep link or a reload survives.
3. **M7-3 The ring on `/confirm` is hidden from screen readers.** With no heading, `ScanRing`'s sentence says "Turn slowly on the spot…", which is wrong after the sweep. Every item is already named and placed in words in the list ("Portable heater. 90 degrees to the right of where you started, a few steps away."), so the ring is purely visual here. Marker radius mirrors engine `DISTANCE_BAND_RADIUS` (0.35/0.65/0.95) locally because contracts/engine are type-only on the phone (R3-4); it is drawing geometry, not a number the user is scored on. The next item to check is circled on the ring and its card is tinted and says "Next to check. Circled on the map." in words.
4. **M7-4 No uncertain items → `/confirm` replaces itself with `/questions`** and announces "Nothing to check". Rejected: an empty screen with a Continue button (an extra tap for the common case).
5. **M7-5 Unchecked items are allowed.** "Continue" (or "Skip checking" when nothing is chosen) sends only the items the person decided; the rest stay as the API left them. Someone who cannot tell is never trapped. The API's `done` stays false while unconfirmed items exist, so `/questions` treats `question === null` as finished once the sweep is at a resting stage, not only `done === true`. If `next-question` returns no question and not done, `/questions` polls the sweep (M1 `pollSweep`) until resting and asks once more; stage `failed` shows "We could not finish reading your room" with "Scan the room again".
6. **M7-6 Number answers are only parsed, not judged.** Spaces and commas are stripped and non-numbers / negatives get a plain-language problem line (the API also rejects negatives in `coerce`). The API's coercion is the authority. `multi_select` answers are sent as the chosen option values joined with commas (the API's default branch takes a string); no tenant question uses multi_select today.
7. **M7-7 "Skip — I'm not sure" is always next to "Next"** and posts `{ skipped: true, value: null }`. Next is disabled until something is chosen/typed; its hint says why.
8. **M7-8 "Questions skipped: N" = `next-question.skipped.length`** (the engine's voi list of fields it chose not to ask), a button with `accessibilityState.expanded` that expands to one row per field: a plain name derived from the canonical path (`buildings[0].yearBuilt` → "Year built") and the API's one-line reason verbatim. At 0 it is plain text, not a button. It is also shown on the finished screen.
9. **M7-9 Question labels.** The visible prompt is the heading (read as "Question N. <prompt>", with the API's `accessibilityLabel` as its hint). Text/number inputs use the API's `accessibilityLabel` as their screen-reader label under a visible "Your answer (unit)" label. Choices use the kit `ChoiceGroup` (radio role, check mark + border when selected); multi-select uses local checkboxes (☑/☐ glyph, not colour).
10. **M7-10 No `src/lib` tests.** M7 owns only the two screen files; its pure helpers (`plainName`, `plainField`, `readNumber`) stay private to them. Nothing new in `src/lib`, so no vitest file.

## Human checklist (iPhone, Expo Go, API running with a sweep that has low-confidence items)

1. **/confirm loads:** after analyzing, the screen shows "Check what we found", a ring with red dots, and one card per uncertain item. Works: the number of cards equals the length of `needsConfirmation` in `GET /sweeps/:id`.
2. **Dots sit where the items were:** an item the camera saw on your right is a dot on the right of the ring; "near" items are closer to the centre. The first unchecked item's dot has a black circle around it and its card is pink with "Next to check".
3. **Confirm / dismiss:** tap "Yes, it's there" on one and "No, it isn't" on another. The chosen button turns black with a ✓ and the card says "You said: …"; a light haptic tick fires; you can change your mind. The circled dot moves to the next unchecked item.
4. **Sends:** tap Continue. Works: `/questions` opens; `GET /sweeps/:id` now lacks the dismissed item and the confirmed one has confidence ≥ the API's confirmed level.
5. **Nothing to check:** with a sweep whose `needsConfirmation` is empty, `/confirm` flashes a skeleton and goes straight to `/questions` (Back does not return to an empty screen).
6. **/questions:** "Question 1" and a large prompt; yes/no questions show two side-by-side options; number questions show a numeric keypad. Next is greyed until you answer. Typing "abc" or "-1" and tapping Next shows "Problem: …" under the field.
7. **Next question arrives:** answer; the Next button spins, then a new prompt appears with the counter +1 and blank inputs. Skip — I'm not sure moves on too.
8. **Skipped counter:** "Questions skipped: N" with "Show why ▼"; tap it — rows appear, each a plain field name and a one-line reason; tap again hides them. Works: N equals `skipped.length` from `GET /sweeps/:id/next-question`.
9. **Finish:** when no questions remain, "That's all we need" + "See my quote" opens `/verdict`.
10. **VoiceOver:** on /confirm the ring is skipped; each card reads "Item 1 of 3: portable heater. 90 degrees to the right… Not checked yet." and the buttons read "Yes, there is a portable heater, radio button". On /questions a new question is announced ("Question 2. Is an extension cord…"); the skipped counter reads "Questions skipped: 3, button, collapsed/expanded"; a network error is announced as "Problem: …".
11. **Largest text (AX5):** buttons wrap to two lines and grow taller, nothing clips or overlaps, the Next/Skip footer stays tappable above the keyboard's home indicator.
12. **Grayscale (Color Filters):** you can still tell chosen from not chosen answers (✓ vs ○, thick border) and which item is next (text, not tint).
13. **Offline:** turn on Airplane Mode and tap Continue/Next — a "Problem: You seem to be offline…" notice with Try again appears; turning the network back on and tapping Try again succeeds.

## Addendum

11. **M7-11 `/questions` wraps its screen in `KeyboardAvoidingView`** (iOS `padding`, offset = safe-area top + 44pt standard header) so Next / Skip stay reachable above the number pad, which has no return key. The 44pt header height is an assumption (no `useHeaderHeight` dependency is installed). Human check: on a number question, tap the field — the Next button must sit just above the keypad, not behind it and not with a large gap.
