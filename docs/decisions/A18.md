# A18 — sweep pipeline, VOI questions, verify-fix: decisions

| # | Decision | Why | Rejected |
| --- | --- | --- | --- |
| D1 | **Stage = the last step whose output is stored.** `createSweep` persists `received` and returns (A15 D1). Each `advanceSweep` runs exactly one step: `received`→gate→`quality_gate`→observe×2→`observing`→relate→`relating`→engine→`scoring`→`questions` (a question or an unconfirmed sighting remains) or `done`. `questions`/`done`/`failed` are no-ops. Any error in a step sets `failed` with `error = "<stage>: <message>"`; advance never throws for a pipeline error. | A15's driver needs one-step advances and a stage that stops moving. | Running the whole pipeline inside `createSweep`. |
| D2 | **What a sweep is scored against.** It is scored against the attached submission's canonical if that submission is `tenant`. Otherwise a renter canonical is built from the row: one building `unit`, `exposure.termMonths` and `roomLabel` as `self_reported` (`sweep:new`). Always the tenant spec/rulebook/rating/questions (read via the E13 `read*` loaders, cached). | A room sweep is a renter quote. The tenant vector is the only one with hazard components. | Scoring a sweep attached to a commercial submission on the commercial vector, which has no room-hazard components. |
| D3 | **FOV = 60°** (`FRAME_FOV_DEG`, exported for the test). It sets both each frame's coverage arc and the object bearing: `frameBearing + (boxCentreX/1000 − 0.5) × 60`. | A phone main camera is ~65° landscape and ~50° portrait. At 60°, 15 frames easily reach 75%, and the 3-photo fallback at 0/120/240 gives 50% (insufficient, so it asks questions). | FOV 10 (the panel width). 15 frames could then never reach 75%. |
| D4 | **Quality gate** (A09 `gradeFrame`) runs in capture order. The duplicate check compares against the previous decoded frame. Passed frames are re-encoded to ≤1024 px JPEG q80 and stored as a data URL in `imageRef`. Dropped frames get `imageRef = null`. With zero kept frames the sweep is `failed` with a re-sweep message. Coverage uses only kept frames, then only model-usable frames. | Keeps the row and the Gemini payload bounded. The crop view still has the frame. | Storing originals, or writing files to disk (no owned directory). |
| D5 | **Model gate.** A frame is usable if either `observe` run marks it usable. `ceilingVisible` is ORed. Unusable frames get `dropped`, `dropReason = "model: <reason>"`. After `applySelfConsistency`, sightings are renumbered `obs-1..n` in its output order. | Deterministic ids, and a single model hiccup does not drop a good frame. | Requiring both runs to agree on usability. |
| D6 | **Ceiling markers** (E12 D3). One derived `unknown` observation `ceiling:f<i>` per usable frame that saw the ceiling. Confidence is 1 if both runs saw it, else 0.5. | E12 counts the ceiling share only through observations. | — |
| D7 | **`relate` output is stored as derived observations**, id `relate:<key>:<present\|absent>:<obsIds joined by +>`, anchored on the first supporting sighting. Only `heaterNearCombustible` and `powerBarOverload` may be returned. At scoring: `present` adds the hazard or re-states its confidence; `absent` can only lower the confidence of an engine hazard (`min(prior, 1 − c)`) and never removes it. A relate hazard is ignored once any of its supporting sightings is pending or dismissed. | PRD 9.2: "this call only adds or adjusts confidence". The schema is frozen and has no other place to keep it between stages. | A second `relate` call at scoring time. |
| D8 | **Sweep facts go to `runEngine` through `enrichment`, with `observations: []`.** E12's `toHazardValues` (on the active sightings) is the single source. The provenance stays `sweep`. The enrichment slot only fixes append order (before answers). | Passing observations as well would make merge count every sighting twice. | Passing raw observations to merge. |
| D9 | **Confirmation (PRD 9.3 step 7).** Sightings under 0.6 are held out of scoring, and every slot they feed (label→keys table) stays **unknown** instead of absent. Confirmed means confidence = `max(c, SOURCE_CONFIDENCE.answer = 0.8)`. Dismissed means removed, together with any relate hazard that leaned on it. | Recording a slot as absent while the user has not yet said whether the candle is real would be wrong. | Scoring pending sightings at their low confidence. |
| D10 | **Session state lives in the result's `canonical.raw.records.retrofit_sweep_session`**, as raw records (answer and fix events). `askedQuestionIds`, answers and fixes are replayed from there on every re-score. The latest answer per question wins. Unknown question ids are ignored. Invalid values (checked by code against the question's type and options) and skips count as asked but carry no value. | The frozen `sweeps` table has no column for answers or fixes. `raw` is the canonical's slot for raw input. | Widening the schema, or adding keys to the stored `EngineResult`. |
| D11 | **VOI** is recomputed after every engine run with the asked ids (`voi(..., asked)`), and replaces `result.voi`. `skippedCount = result.voi.skipped.length`. `nextQuestion.done` = no question and no pending confirmation. Answers before the sweep is scored throw. | `runEngine` does not pass asked ids. | — |
| D12 | **Verify-fix.** The key accepts `x`, `hazards.x` or `hazards.present.x`. It must be a binary `hazards.*` tenant component (a count such as smoke detectors is answered, not photographed). The photo goes through the same code quality gate first; if it fails there is no model call and the result is `stillPresent true, confidence 0`. The model's answer is **credited only if `stillPresent = false` and `confidence ≥ 0.6`** (code gate). A credited fix **replaces** the hazard's sweep value and any answer for that key with `false` (`sweep`, `verify-fix:<capturedAt>`). Every fix attempt is recorded as a session event. `before` = snapshot of the stored result, `after` = the new one, `rank = null`. | Appending `false` next to the old `true` would open a HIGH contradiction and turn every fix into REFER. The fix is a real change in the room, not a disagreement between two sources. | Appending the fix value; letting the model's word flip the value at any confidence. |
| D13 | Functions shared by `questions.ts` and `verify-fix.ts` are exported from `sweep.ts` and marked `@internal A18`. `snapshotOfResult` is a private copy, because `snapshotOf` belongs to A16 (not a dependency, still a stub). | Same unit. No new shared helper module. | Duplicating the scoring code three times. |

## Upstream issue found (not A18's to fix)

`vectorize` (E05) and `evaluate` (E06) are commercial-only right now. `evaluate`
loops over the eight Federato `APPETITE_FACTORS`. `vectorize` reads `hazards.<key>`
through `asNumber(readSource(...))`, which yields `null` for the merged boolean
hazard slots (they live under `hazards.present.<key>` and hold booleans). So a
tenant `EngineResult` has every hazard component missing and scores against the
commercial factors. What A18 hands the engine is correct and is asserted exactly
in `sweep.test.ts` (through a `runEngine` spy). The tenant score, verdict and
price only become meaningful once E05 and E06 handle the tenant spec. The tests
therefore assert those values only as "the snapshot equals the stored result",
never as specific numbers.
