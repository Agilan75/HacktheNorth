# E05 — decisions (stage 6: vectorize, scaling, book stats)

All five decisions below were open in the PRD/contracts. INTERPRETATIONS.md was
never re-decided; where it speaks, it is copied verbatim.

## 1. `tiersFor` reads the frozen constants, not the rulebook's rules

**Decision.** The tier boundaries come from `constants.ts` (TIV_*, PREMIUM_*,
LOSS_ACCEPTABLE_MAX, MAJORITY_SHARE, TARGET/ACCEPTABLE_STATES) exactly as
INTERPRETATIONS §3 states them. The `rulebook` argument is carried on the
signature but not read.

**Why.** `packages/engine/rules/commercial.json` does not exist yet (E13, same
run) and `evaluateConditions` is E01's; E05 has no Run-1 dependencies, so a
rule-driven implementation could neither run nor be tested. The constants and
the rulebook JSON must encode the identical numbers, so the two agree by
construction.

**Rejected.** Firing the rulebook's rules through `vectorResolver` — correct
architecture, unavailable in Run 1, and it would have made this unit blocked.
Replacing the body with a rule walk later needs no contract change.

## 2. `bestValue` is duplicated privately

`util/fields.ts` (E01) was still `NOT_IMPLEMENTED` when E05 ran, so
`vectorize` carries a private `pickValue` implementing the rule that file's
docstring states: highest confidence, ties by `enrichment > answer > sweep >
self_reported`, then latest `observedAt`, then insertion order. Marked
`TODO(contract)` in the source. **At the checkpoint, swap it for the import** —
only the two slots `submissionType` and `pricing.quotedPremium` use it.

## 3. `ComponentStats.mean` / `.median` are in RAW space

`min`/`max` are post-transform, as the frozen type comment and INTERPRETATIONS
§6 both say. The comment qualifies only `min`/`max`, so `mean` and `median` are
left in raw space, which is also what a pricing or explanation fallback wants
(a dollar figure, not a log). Empty column ⇒ `min = max = mean = median = 0`,
`count = 0`, which makes `minMax` degenerate and scales every input to 0.

## 4. Scaling with no `BookStats`

A `minmax` / `log_minmax` / `log1p_minmax` component with `stats === null`, or
with no entry for its index, scales to **0** — the same result a degenerate
range gives (§6). `none` is used as-is and `divide` uses `divisor ?? 1`.

**Rejected.** Falling back to the spec's `min`/`max` bounds: it invents a
scaling space the differential oracle does not define.

## 5. Book-wide fallbacks on `BookStats`

Derived from the vectors alone, because that is all `computeBookStats` receives:

- `medianRatePer100` = median of `quotedPremium ÷ (totalTiv ÷ 100)` over
  accounts where both components are known and TIV is non-zero.
- `meanAnnualLoss` = mean of `fiveYearLoss ÷ 5` (`LOSS_WINDOW_YEARS`).
- `meanClaimFrequency`, `meanClaimSeverity` = **null**. Claim counts and
  severities are not vector components and cannot be derived here; a consumer
  that needs them must compute them from the canonical submissions.

`n` counts every vector passed in, including ones with missing components.

## 6. Defensive case: only one of components 5/6 known

INTERPRETATIONS §V-6 guarantees `pctTivPre1990` and `pctTivPost2010` are jointly
known or jointly missing. If one is nonetheless null, the age tier is computed
from the other (the `> 0.5` test on the null side is skipped) rather than
nulling the factor, so a knockout is never silently lost. Both null ⇒ both
tiers null.
