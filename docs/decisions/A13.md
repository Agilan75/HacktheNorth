# A13 — run/enrich + aggregate routes: decisions

1. **`POST /submissions/:id/run` re-runs enrichment, then the engine** (PRD §8
   literal). If the enrichment runner itself throws, the engine still re-runs on
   the values stored by the last enrichment (read back from `enrichments.payload.values`).
   Rejected: run = engine only on stored values (contradicts PRD "re-run enrichment").

2. **Only `available` outcomes feed `rescoreOne({ extra })`.** An "unavailable"
   card is stored and shown but moves nothing.

3. **Every outcome is persisted** via `enrichments.upsert` with id
   `${submissionId}:${source}` (deterministic, no randomness; the repo keeps the
   first id on conflict). `payload` = `{ card, values, raw, unavailableReason, durationMs }`.

4. **`EnrichLocation` is built from the canonical record**: first non-null value
   of each `Sourced` slot in insertion order; `address` is null (LocationFacts has none).

5. **Errors:** unknown id → 404 `NOT_FOUND`; submission without `canonical` →
   409 `NOT_NORMALIZED` (nothing to score); service failures fall through to the
   app's 500 `INTERNAL`.

6. **`GET /aggregate`** returns `services/aggregate.aggregate(deps)` unchanged.
