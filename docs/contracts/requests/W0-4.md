# Contract requests — W0-4 (UI, verify and mobile skeletons)

## 1. Console panel props are not yet typed against `@retrofit/contracts`

**Status:** worked around locally, no action needed before CP0.

`apps/console/src/panels/types.ts` froze while W0-3 was still writing
`packages/contracts/src/dto.ts`, so every panel prop is declared there as a
*structural subset* of the DTO PRD §10 implies (`QueueRowView`,
`SubmissionDetailView`, `FactorRowView`, `PricingView`, `PeerBenchmarkView`,
`FlipView`, `VectorView`, `EnrichmentCardView`, `RoutingView`,
`RequestDraftView`, `ExtractedFieldView`, `ActionLogEntryView`, `SweepView`,
`ReplyResultView`, `SchemaView`, `QueryTraceEntryView`, `ExplanationView`,
`ContradictionView`, `InterpretationView`, `BuildingRowView`, `RollupView`,
`CitationView`).

**Requested at CP0, by whoever applies contract changes:** check these against
`packages/contracts/src/dto.ts`. Where a real DTO exists with the same meaning,
the DTO should remain *assignable* to the view type — that is, the DTO may have
more fields, but every field named above should exist with the same name, type
and units (dollars as plain numbers, shares in `[0, 1]`, ISO strings for
timestamps). Any field the DTO spells differently should be renamed in the DTO
if it is new, or reported back so W0-4's frozen file is patched once, at the
checkpoint, before C01–C14 start.

C01 types the API client against `@retrofit/contracts` and passes those objects
straight into the panel props, so a structural match is all that is required.
