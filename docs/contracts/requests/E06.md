# Contract request — E06

## File

`packages/engine/src/types.ts` — `VectorComponentSpec`.

## Exact change requested (additive)

```ts
export interface VectorComponentSpec {
  // ... existing fields ...
  readonly direction?: Direction;
  readonly appetiteFactor?: boolean;
  readonly factor?: FactorId;
  readonly extensionOnly?: boolean;
  readonly immovable?: boolean;
}
```

## Why

`packages/engine/vectors/commercial.json` and `tenant.json` carry `direction`,
`appetiteFactor`, `factor`, `extensionOnly` and `immovable` on every component,
and INTERPRETATIONS T-SPAN and F-2 depend on them (`factor` maps components to
the eight appetite factors; `immovable` is the flip's blocklist). The frozen
`VectorComponentSpec` type does not name any of them, so the data file and the
type disagree. `evaluate` needs `factor` to group components into factors, and
E08 (`flip`) needs `immovable`.

## Local workaround in use

`evaluate.ts` declares a private `ComponentExtras` interface and reads the spec
through `VectorComponentSpec & ComponentExtras`, falling back to a private
`DEFAULT_FACTOR_BY_KEY` map when `factor` is absent. No frozen file was touched
and no shared helper was added. When the type is widened, the widening cast can
be deleted and the fallback map kept as the defensive default.
