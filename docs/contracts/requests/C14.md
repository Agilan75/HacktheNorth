# C14 contract request — richer AggregateResponse (additive)

**File:** `apps/console/src/api/client.ts` (owner C01), `AggregateResponse` + `aggregateView`.

**Change (additive, optional fields):**
- `counts?: { total: number; scored: number; knockedOut: number; byLine: Record<string, number> }` — pass through `dto.counts`.
- `topKnockoutFactors[].label?: string` — pass through `f.label`.
- `bookAdequacyDetail?: { median: number | null; underpricedCount: number; n: number }` — pass through `dto.bookAdequacy`.
- `oneFlipMoves?: Record<string /* submission id */, { moveLabel: string; scoreAfter: number; premiumAfter: number | null }>` — from `dto.oneFlipAway`, so the move label is not lost when the queue row replaces it.
- `verification` as `null` rather than `{}` when no run exists (or leave as-is; the page handles `{}`).

**Why:** PRD 10 asks for "book adequacy" and the "one-flip-away list"; without these the page shows only the median and the queue explanation, not the underpriced count or the specific flip move.

**Workaround in place:** page sums `countsByVerdict`/histogram for totals, uses `titleCase(factorId)` for labels, shows `explanationLine` in the flip column, shows only the median adequacy. Once the fields exist, AggregatePage can read them with a one-line change each.
